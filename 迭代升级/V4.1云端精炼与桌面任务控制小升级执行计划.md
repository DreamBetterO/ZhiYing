# V4.1 云端精炼与桌面任务控制小升级执行计划

状态：`approved_ready_for_execution`（方案已命名并批准；产品代码尚未开始修改）

版本：**V4.1**

版本类型：**小版本升级**。本轮不改变 15 步主阶段顺序、CourseIR、Canonical Document v2、桌面产品边界或 JSON → Markdown → Word → PDF 主合同；通过增加编辑意图、编辑决策、聚合降级和桌面任务控制能力完成向后兼容升级。若实施中发现必须改变这些核心合同，停止当前 Phase 并由用户重新确定版本类型，不得静默扩大为大版本。

基线：V4.0 / 产品版本 `0.4.0`

拟交付产品版本：`0.4.1`，只允许在最终门禁全部通过后统一更新。

## 0. 执行结论

V4.1 必须一次解决以下七组用户问题，不能只修界面或只换提示词：

1. 云端与聚合链路能识别输出截断、按输出预算分批、保存成功批次、从检查点恢复，并在云端失败时生成真实本地产物。
2. “课程资料整理偏好”只表达最终文档的组织行为和关注重点；用户不填写 JSON 字段、章节数、知识点数或门禁参数。
3. 大模型在现有规划调用中形成可审计的编辑决策，在现有精炼调用中执行该决策；不增加额外云端调用。
4. 聚合结果必须真正渲染模型精炼后的正文，来源原始 `content_blocks` 不得覆盖云端改写内容。
5. 聚合成为本地/云端处理模式，视频超过一个即可开启；队列顺序由鼠标拖动决定。
6. Desktop 与 CLI 的资源型命令全局单实例；重复 CMD、Desktop 与 CLI `run` 之间互斥，但不得阻断 `video-study://` 播放。
7. “清除所选缓存”安全删除所选视频 Workspace、Output 和失效的派生聚合结果；产物按钮只在文件完整落盘后出现。

执行依赖顺序：

```text
P0 冻结合同和测试归属
→ P1 编辑意图与编辑决策合同
→ P2 精炼写作、门禁和正文唯一所有权
→ P3 云端截断、分批、日志和检查点恢复
→ P4 本地/云端统一聚合模式
→ P5 拖动排序、缓存清理和产物可见性
→ P6 全局单实例与 Workspace 冲突防御
→ P7 一次性集成验收、真实云端授权验收与交付
```

一次只允许一个 Phase 为 `in_progress`。未达到本 Phase 收敛门，不得进入下一 Phase，也不得用后续 Phase 的改动掩盖当前失败。

## 1. 永久边界与不可损害能力

### 1.1 本轮必须保持

- 原生 Windows Desktop；不增加 Web UI、HTTP 服务、端口监听或 `serve`。
- 保持现有 15 个 Step ID、顺序和依赖关系；V4.1 不增加新的主流水线 Step。
- CourseIR 仍是云端写作输入的领域权威，Document v2 的 `content_blocks` 仍是三端渲染唯一正文事实源。
- 保持源视频不上传、不复制；云端不接收视频、截图、本地路径、Markdown、Word、PDF 或完整 `document.json`。
- 保持时间戳、source ID、视觉证据 ID 与 `video-study://` 本地回看。
- 云端继续 opt-in。每次真实请求前展示发送数据、端点、模型链和完整预算，并重新取得明确授权。
- 未授权、模板预检失败或预算不足时，CloudPort 构造和真实请求次数均为 0。
- 本地 ASR、本地 VLM、视觉 `no_match`、任务取消、缓存命中、局部重跑、Word/PDF fallback 均不得回归。
- 保持旧 Workspace 可读，不主动删除历史 Workspace；只由用户明确触发清理。
- 不读取、输出、缓存或提交 `.env` 中的秘密。

### 1.2 明确不做

- 不引入新的文本大模型、本地 LLM、LangGraph、数据库、向量库或后台常驻服务。
- 不让模板描述机器 Schema、来源 ID 规则、Token、模型名或渲染字段。
- 不给模板增加配置路径、YAML 表单、章节数量、知识点数量和必填栏目。
- 不通过自动补括号接受被截断的课程 JSON；不能用“可解析”掩盖内容丢失。
- 不把云端质量不理想自动解释为成功；也不因文风偏好触发无上限模型重试。
- 不为了测试重跑长视频 ASR、重复加载真实 VLM、遍历全部模型或重复生成相同 Word/PDF。
- 不维护新旧两套聚合生产路径；新路径稳定后删除被取代的按钮命令和重复编排。

## 2. 模板、模型与程序的责任合同（V4.1 核心）

### 2.1 “模板”改为编辑意图，不是提示词配置表

产品内置并自动加载一个可编辑 Markdown 文件：

```text
课程资料整理偏好.md
```

文件位置由应用约定统一管理，不在 `config.yaml` 暴露路径，不要求用户理解项目目录。Desktop 只提供：

- `编辑整理偏好`：用系统默认文本编辑器打开该文件。
- `恢复默认偏好`：从随产品发布的默认 Markdown 资源恢复；恢复前确认，不触发云端。

默认模板只写自然语言编辑意图，建议内容不超过四段：

```markdown
# 课程资料整理偏好

希望最终文档形成适合系统学习和复习的正式课程资料。

优先提炼全课主线，再根据内容关系组织章节；如果课程明显按照演示、推导、案例或操作步骤逐步展开，可以保留老师讲课的时间顺序。

重点关注概念定义、判断条件、推导关系、操作步骤、案例结论、容易混淆的地方，以及老师反复强调或明确提醒的内容。

删除寒暄、口头语和无信息重复。详略由知识的重要程度、理解难度和课程强调程度决定，不平均分配篇幅。
```

用户可将其改成一句或数段自然语言。程序只做 UTF-8、非空、大小上限和路径安全检查，不解析标题或把自然语言转换成大量配置项。

### 2.2 指令优先级

发生冲突时按以下顺序处理：

1. **程序安全合同**：来源真实性、ID 合法性、不上传受限数据、完整 JSON、预算、取消和产品边界。
2. **用户编辑意图**：总分/时间/主题/案例/步骤结构倾向，重点关注内容和表达要求。
3. **模型编辑决策**：在没有明确用户指令的部分，根据课程形态自主选择结构和详略。
4. **默认偏好**：只有用户模板没有明确说明时才补足，不覆盖用户表达。

模板中如果要求补充外部知识、伪造图片或移除来源追踪，相关要求必须被安全合同拒绝；其余文档行为偏好应由模型执行，不能被固定栏目门禁覆盖。

### 2.3 编辑决策由现有规划调用生成

V4.1 不增加一次“模板分析请求”。现有 `knowledge.plan` 云端规划请求同时消费：

```text
压缩转写 SourceBlock
+ 课程资料整理偏好文本
+ 内容档位/图文档位
→ LessonPlan + editorial_decision
```

`editorial_decision` 作为 `knowledge.plan` Artifact 的向后兼容新增字段，至少包含：

```json
{
  "brief_sha256": "...",
  "structure_mode": "thematic_hierarchy | lecture_timeline | process | case_driven | hybrid",
  "core_thread": "模型识别的课程主线",
  "focus_priorities": ["需要重点保留的内容类型或课程主题"],
  "sequence_policy": "reorganize | preserve | hybrid",
  "decision_reason": "简短、可审计的选择理由"
}
```

约束：

- `brief_sha256` 由本地计算；模板正文不写入运行日志，只记录 hash、字符数和是否使用默认模板。
- `structure_mode` 是模型的内部决策，不要求用户选择枚举。
- `decision_reason` 只用于 Workspace 审计，不默认渲染到课程文档。
- 规划模型自主决定章节和 UnitPlan，但只能引用真实 SourceBlock。
- 用户明确要求时间结构时，模型不能无理由改为主题结构；用户写“自动判断”或未指定时，模型可自主决定。
- 内容档位只影响总体篇幅预算；不得再转换成“每章必须 N 个知识点”或“每点必须填满所有 facet”。

### 2.4 精炼模型执行决策，不重新发明一套结构

现有 `knowledge.units` 云端精炼请求消费：

```text
紧凑 CourseIR
+ 同一份编辑意图
+ editorial_decision
→ 课程正文 content_blocks + 复习信息
```

精炼模型拥有以下自主权：

- 在规划选择的真实来源范围内合并重复表达、删除口头填充、重新表述并分配详略。
- 自主选择 paragraph、rule_list、steps、example、pitfall 和 visual_group；来源没有对应信息时不必输出该栏目。
- 自主决定是否需要学习目标、章节摘要、复习清单或未展开问题。
- 对同一 Claim 只选择一个主要展示位置，避免正文、规则、步骤和复习提示重复。

精炼模型不能：

- 引用规划范围外的 source/unit/claim/visual ID。
- 把模型推断写成课堂事实。
- 改写时间戳、图片路径或 `video-study://` URL。
- 忽略规划选择的 UnitPlan。这里的“逐项覆盖”只保护已选择课程内容不丢失；哪些内容进入 UnitPlan 由规划模型决定，不由固定模板决定。

### 2.5 本地与云端责任边界

- **云端成功**：完整执行自然语言编辑意图和 `editorial_decision`。
- **规划云端失败、精炼云端仍可用**：本地生成保守 LessonPlan 和 `lecture_timeline` 决策，精炼模型仍收到用户编辑意图，可在安全范围内调整结构。
- **精炼云端失败**：使用本地 CourseIR 生成保守正文，状态为 `degraded`；不宣称已完成模型级精炼。
- **纯本地模式**：不尝试解释任意自然语言模板，只保证来源顺序、内容保真、去除可确定的完全重复和完整产物链。
- **本地聚合**：按队列顺序和现有章节保守组合，保留来源；不伪装成跨视频语义重组。

### 2.6 模板与缓存

模板的规范化 SHA-256 必须进入：

- `knowledge.plan` 指纹。
- `knowledge.units` 指纹。
- 云端聚合输入/检查点指纹。

模板变化只使规划、知识单元、文档组装、渲染和聚合失效；不得重跑音频、ASR、候选帧或关键帧。模板未变化时必须正常命中缓存。

## 3. 质量门禁：硬门、软审计和停止条件

### 3.1 硬门禁（不满足不能接受云端结果）

1. 模板文件可安全读取，UTF-8、非空且不超过约定上限；失败发生在请求前。
2. 请求输入、预计请求数和输出预算在用户本次授权范围内；预算不足时请求数为 0。
3. 响应 `finish_reason` 不是截断状态，JSON 对象完整可解析。
4. 所有 source/unit/claim/visual ID 都来自本次允许集合。
5. 已进入 LessonPlan 的 UnitPlan 恰好有一个主要正文归属，不能丢失或重复输出。
6. 每个课程事实存在来源引用；模型辅助说明必须保留 `model_aid` 标识。
7. 图片只能使用本地已验证 `visual_id`，不能创建新图片或路径。
8. Document v2 可验证，Markdown、Word、PDF 都从同一 Document v2 生成。

硬门失败的行为：

- 云端截断/格式/引用失败：按 P3 策略恢复或降级，不接受残缺内容。
- 取消：立即停止，不降级为新的长任务。
- 本地 Artifact 损坏、ASR 无结果等不可恢复输入错误：任务失败且不得静默排除所选视频。

### 3.2 软质量审计（不触发盲目模型重试）

以下只进入 `knowledge.selfcheck` 和运行摘要：

- 标题与正文开头重复。
- 同一句在 overview、正文、review 中完全重复。
- 口头填充词密度过高。
- 详略分配过于平均或重点内容过短。
- 用户强调项在编辑决策中未体现。
- 可选的学习目标、摘要、复习清单为空。

软审计不得因为固定数量不满足而换模型。只有硬门失败才允许消耗 fallback 请求；风格不理想留给用户检查和后续明确重跑，避免隐藏消耗额度。

### 3.3 正文唯一所有权

- 单视频云端正文以模型返回并验证后的 `content_blocks` 为权威。
- 聚合云端正文必须由聚合结果生成新的 `content_blocks`；来源文档的原始 `content_blocks` 只作为输入证据，不能直接挂回聚合知识点覆盖新正文。
- 来源链接、时间范围和图片由本地根据 `source_point_ids` 回填，不由模型生成。
- 视觉组只保留一个导语、一个图注和一个理解结论；完全相同文本不得在 alt、图注和 takeaway 中连续展示三次。
- Markdown、Word、PDF 渲染器只渲染 Document v2，不承担课程内容选择或二次改写。

## 4. 云端截断、分批和恢复合同

### 4.1 Provider 结果信息

每次模型尝试必须记录但不得记录响应正文：

- stage / batch ID / model。
- 请求序号、授权上限和剩余额度。
- prompt chars、response chars。
- prompt/completion/total tokens。
- finish reason。
- 结果分类：success、truncated、invalid_json、schema_rejected、timeout、connection、http_status。

稳定错误码：

```text
CLOUD_OUTPUT_TRUNCATED
CLOUD_OUTPUT_INVALID_JSON
CLOUD_OUTPUT_SCHEMA_REJECTED
CLOUD_TIMEOUT
CLOUD_BUDGET_EXCEEDED
```

`finish_reason=length` 或没有完整闭合 JSON 且达到输出上限时归类为截断。截断不得在 Provider 内对其他模型盲发同一个超大请求；由聚合/知识编排层决定缩小批次或降级。

### 4.2 输出感知分批

聚合批次不能只按输入字符拆分，必须同时估算：

- 输入字符数。
- source point / unit 数量。
- 每个内容档位的预计输出 Token。
- 最终合并请求所需空间。
- 授权请求数和至少一个恢复余量。

中间批次只返回紧凑结构：

```json
{
  "course_units": [
    {
      "statement": "精炼后的知识陈述",
      "body": "必要解释",
      "source_point_ids": ["point_0001"]
    }
  ]
}
```

中间批次不得重复生成 document title、overview、learning objectives、review、examples、conditions、pitfalls 等完整最终结构。最终合并请求才根据编辑意图决定课程结构和可选复习信息。

### 4.3 检查点与恢复

每个成功批次立即原子写入聚合 Workspace：

```text
state/aggregate-checkpoints/<fingerprint>/batch-0001.json
state/aggregate-checkpoints/<fingerprint>/index.json
```

指纹至少包含：有序来源文档摘要、编辑意图 hash、聚合器版本、内容档位和输出合同版本。API Key 不得进入指纹或文件。

重跑规则：

- 指纹一致且批次通过本地 validator：直接复用，不请求云端。
- 指纹变化：只使本次聚合检查点失效，不删除历史源视频 Workspace。
- 批次成功、最终合并失败：保留批次；下一次获得新授权后只执行未完成部分。
- 云端预算耗尽或所有模型失败：生成本地聚合 Document v2，运行状态 `degraded`，日志保留真实失败原因。

## 5. 聚合模式与桌面交互合同

### 5.1 聚合模式

- 原“聚合所选”命令改为可切换的“聚合模式”。
- 勾选视频数大于 1 时可开启/关闭，不要求视频已完成。
- 开启时按钮绿色，关闭时灰色；少于两个选择时自动关闭并禁用。
- 队列顺序是单视频处理顺序、本地聚合顺序和云端聚合来源顺序。
- 聚合模式开启后：
  - `本地整理`：逐个完成/复用本地结果，然后自动本地聚合。
  - `云端优化`：逐个完成/复用云端结果，然后自动云端聚合；云端阶段失败时自动本地聚合并标记降级。
- 聚合模式关闭后：保持现有单视频批处理，不生成聚合结果。
- 任一所选视频发生不可降级的媒体/ASR/Artifact 错误时，不得静默排除该视频生成“成功聚合”。

云端授权文案必须显示：发送编辑意图文本、压缩转写/课程来源 ID；端点；模型链；所选视频数；单视频上限；聚合上限；理论总上限。不发送视频、截图、本地路径和密钥。

### 5.2 鼠标拖动排序

- 删除“上移所选/下移所选”。
- 空闲状态下按住任意视频行拖动，显示目标插入位置，松开后一次提交新顺序。
- 点击复选框只改变勾选状态，不开始拖动。
- 有效拖动后抑制该次双击打开视频，避免误操作。
- 运行、准备和取消状态不允许拖动。
- 顺序变化使旧聚合结果失效，但不删除单视频缓存。

### 5.3 清除所选缓存

- “删除所选产物”改名为“清除所选缓存”。
- 明确删除所选视频的 Workspace 与对应 Output；源视频永远保留。
- 同时清除队列结果、Token、进度、产物路径和引用这些视频的聚合结果/检查点。
- 保留“清理全部缓存”作为独立高风险操作。
- 运行期间禁止清理；所有目标经 WorkspaceCatalog 安全根检查，拒绝项目根、用户目录、磁盘根、符号链接逃逸和不属于本项目的路径。

### 5.4 产物可见性

- Markdown、Word、PDF 按钮初始不创建可见占位，或使用 `grid_remove` 隐藏。
- 仅当恰好选择一个已完成视频，且对应文件真实存在时分别显示。
- 处理中、失败、取消、清除缓存、路径丢失或多选时隐藏。
- 聚合文档按钮只在聚合 Document v2 和目标文件完整落盘后显示。
- 文件存在性是最终条件，不能只依赖进度 100% 或内存中的旧 result。

## 6. 全局单实例与冲突解决合同

### 6.1 锁范围

Windows 使用系统命名互斥量，键由产品标识和规范化资源根摘要构成。以下命令获取同一把资源锁并持有到进程退出：

- `video-study desktop`
- `video-study run`

以下命令不持有资源锁：

- `doctor`：只读诊断。
- `play-url`：必须允许由 Word/PDF 在 Desktop 存活时启动本地播放器。

第二个资源实例：

- 在加载 ASR/VLM、启动线程或调用 Word 前立即失败。
- Desktop 显示“知影已有任务实例正在运行”。
- CLI 写入简洁 stderr 并返回稳定非零退出码。
- Windows 在进程崩溃后自动释放 mutex，不使用固定超时假定实例仍存活。

### 6.2 Workspace 第二层锁

保留现有 Workspace lease，补充 PID 存活检测和原子竞争处理：

- PID 活跃：拒绝并报告占用 run。
- PID 不存在或 lease 损坏：安全回收，不固定等待六小时。
- 只释放由当前 run_id/PID 持有的 lease。
- 全局 mutex 负责资源互斥，Workspace lease 负责同一 Artifact 的第二层防护；不能删除任一层。
