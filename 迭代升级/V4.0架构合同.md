# V4.0 架构合同

状态：`approved`

适用变更：`architecture-decoupling-pipeline-kernel`

本文件保存 V4.0 的长期稳定架构约束，不保存实施进度。执行动作、阶段状态、测试结果和交付记录分别归属于 [Agent 执行清单](架构解耦与可恢复执行内核升级Agent执行清单.md)、`当前架构升级状态.yaml` 与 `执行事实.yaml`。

合同变更规则：执行 Agent 不得因局部实现便利自行偏离本合同。若现状证据表明合同不可行，必须暂停当前 Phase，在状态文件记录冲突、影响和最小替代方案，经用户确认后再修改合同与清单。

## 2. 目标架构与依赖方向

### 2.1 最小充分结构

```text
desktop/（View + Controller） / cli.py
        ↓
application/processing.py（用例服务、请求/结果 DTO）
        ↓
pipeline.py（稳定兼容门面，仅保留 process_video/run_all）
        ↓
execution/
  context.py       ProcessingContext、RunPolicy、RuntimeServices
  contracts.py     StepSpec、PipelineStep、StepOutcome、ErrorInfo
  artifacts.py     ArtifactId、WorkspaceLayout、ArtifactStore、WorkspaceCatalog
  cache.py         WorkspaceCache、CacheRecord、CacheDecision
  ports.py         Media/Speech/Vision/Cloud/Document 端口
  runner.py        PipelineRunner、状态机、动态任务组
  registry.py      唯一 Step DAG 与影响范围
  bootstrap.py     唯一 composition root，连接现有 adapter
  steps/           只做步骤输入组装、调用领域能力、输出校验
        ↓
领域模块：transcript.py、knowledge/*
        ↓
现有基础设施 adapter：media.py、asr.py、providers.py、
execution/adapters/vision.py、render.py、localplay.py、utils.py
```

不引入 DI 框架、插件框架、数据库、消息队列、Web 服务或事件溯源产品。使用标准库 `dataclass`、`Protocol`、显式 Registry 和 JSON sidecar 即可。

Desktop 目标结构：

```text
src/video_study/application/
  __init__.py
  processing.py       ProcessingService：处理、聚合、缓存查询和清理用例
  requests.py         ProcessingRequest、CloudAuthorization、公开结果 DTO

src/video_study/desktop/
  __init__.py         继续导出 launch_desktop，保持既有 import
  view.py             Tk 控件、文件选择、messagebox、root.after 和样式
  controller.py       队列/命令/状态机；只依赖 ProcessingService 协议
  models.py           QueueItem、DesktopState、UiEvent 等无 Tk DTO
  settings.py         桌面设置校验/保存和凭据持久化边界
```

现有 `desktop.py` 最终转换为 `desktop/` package；`from video_study.desktop import launch_desktop` 和 CLI 行为保持不变。不得同时长期保留 `desktop.py` 与 `desktop/` 两套实现。

### 2.2 允许依赖

| 层 | 可以依赖 | 禁止依赖 |
|---|---|---|
| Desktop View | Controller、Desktop DTO | ProcessingRunner、Artifact、provider、业务算法、直接 Workspace I/O |
| Desktop Controller/CLI | `application.processing`、公开请求/结果 DTO | `knowledge.*`、缓存文件、ASR/VLM/provider 内部实现 |
| Application Service | `pipeline.py` 门面或 execution bootstrap、WorkspaceCatalog | tkinter、供应商 SDK、Artifact 内部路径 |
| `pipeline.py` 门面 | `execution.bootstrap`、公开 DTO | 具体 Step、直接 JSON I/O、外部中间件 |
| execution | contracts、ports、Artifact/Cache、Step adapter | tkinter、环境变量读取、供应商 SDK |
| Step adapter | execution contracts、领域服务、ports | 桌面、直接 subprocess、直接 OpenAI、直接缓存文件 |
| 领域模块 | 领域模型和纯函数 | execution、desktop、Workspace、环境变量、外部中间件 |
| 基础设施 adapter | ports、第三方/系统能力 | 桌面状态、Pipeline DAG、业务缓存策略 |

### 2.3 最终清洁度硬指标

- `pipeline.py` 是薄门面，不再直接调用 `extract_audio/transcribe/extract_keyframes/build_document/render_*`。
- `summarize.py` 被删除；如迁移中暂留，只能作为无业务逻辑的短期兼容导出，并在 P8 删除。
- Desktop View 不直接处理队列业务、线程执行、缓存、聚合、凭据解析或 Workspace 路径。
- Desktop Controller 可以在不创建 Tk root 的情况下完成全部状态转换测试。
- `knowledge/*` 不再导入 `summarize`、`pipeline`、`desktop` 或 Workspace 实现。
- 核心生产路径不再使用 `_runtime_*`、`_event_callback`、`_progress_event_callback` 等隐藏 settings 字段。
- 除 `execution/artifacts.py`、迁移 adapter 和测试 fixture 外，源码不得硬编码 Workspace 中间产物文件名。
- 业务模块不得直接执行缓存读取、缓存签名判断或缓存写回。
- 失败/取消不覆盖上一份有效产物和 CacheRecord。
- 新执行内核稳定后只保留一个生产 Runner，不保留新旧 Runner 总开关。
- 默认生产配置不再暴露已退役的 legacy 选择开关。
- 包名和描述不再包含 `demo`，但 CLI 命令 `video-study` 保持不变。

## 3. 核心合同

### 3.1 ProcessingContext

目标接口：

```python
@dataclass(frozen=True)
class ProcessingContext:
    run_id: str
    source: VideoSource
    workspace: WorkspaceLayout
    options: ProcessingOptions
    policy: RunPolicy
    services: RuntimeServices
```

约束：

- `VideoSource` 只保存解析后的来源身份：绝对路径、video_id、快速指纹、时长、大小。
- `ProcessingOptions` 是从 `AppConfig` 编译出的只读、无秘密配置快照；至少把 ASR、Frames、Knowledge、Visual、Render 分段。
- `RunPolicy` 保存请求意图：cloud 是否获授权、内容档位、视觉档位、目标 Step、force/rerun 范围和重试规则。
- `RuntimeServices` 保存不可序列化运行依赖：取消令牌、事件 sink、进度 sink、时钟、懒加载中间件端口和单视频云预算账本。
- API Key 字段必须 `repr=False`、`compare=False`，不得进入 Context 序列化、事件、CacheRecord 或指纹。
- Context 不存放阶段输出，不作为可变全局状态，不允许单例。
- 可变步骤状态只由 `PipelineRunner` 持有的 `PipelineRunState` 修改。

### 3.2 PipelineStep

目标接口：

```python
class PipelineStep(Protocol):
    spec: StepSpec

    def fingerprint(self, context, inputs) -> FingerprintMaterial: ...
    def execute(self, context, inputs, staging_dir) -> StepOutcome: ...
    def validate(self, context, outcome) -> None: ...
```

`StepSpec` 必须声明：

- 稳定 `step_id`，禁止把版本号写进 ID。
- `implementation_version`。
- 上游 `dependencies`。
- 输入和输出 `ArtifactId`。
- 影响指纹的配置键。
- `remote_cost`: `none/local_heavy/cloud`。
- 允许的结果能力和降级策略。
- owner 模块、对应测试和默认错误码前缀。

Step 禁止：

- 自行修改 Manifest 或 PipelineRunState。
- 自行决定全局下游失效。
- 自行读写 CacheRecord。
- 直接访问 tkinter、环境变量或凭据文件。
- 为命中检查提前创建 ASR/VLM/cloud/Word provider。

### 3.3 StepOutcome 与状态机

统一状态：

```text
pending → checking_cache → cached | ready → running
        → succeeded | degraded | skipped | failed | cancelled
```

规则：

- `succeeded`：满足本次请求能力。
- `degraded`：产物有效但能力低于请求，例如获授权的云端整理失败后使用离线结果。
- `skipped`：步骤不适用，例如无视觉问题。
- `no_match` 是视觉领域成功结果，不是 Step 失败。
- `failed/cancelled` 不提交新的成功 CacheRecord。
- 每个 Outcome 包含 `step_id`、`run_id`、`error_code`、`capability`、ArtifactRef 和脱敏诊断信息。
- 离线降级产物可以满足后续离线请求，但不能冒充成功的 cloud 产物阻止未来云端重试。

### 3.4 PipelineRunner

Runner 是唯一编排者，按以下顺序执行每一步：

1. 验证 DAG 和请求目标。
2. 收集已验证上游 ArtifactRef。
3. 生成规范化指纹材料。
4. 请求 WorkspaceCache 判定。
5. 命中时恢复并验证，不初始化中间件。
6. miss 时在 Step 专属 staging 目录执行。
7. 校验成功后原子提交 Artifact。
8. 最后提交 CacheRecord 和 PipelineRunState。
9. 发布结构化事件、进度和 ETA。
10. 失败时仅阻断必要下游，保留已成功产物。

### 3.5 动态任务组

视觉 compare/detail 和云端分章整理不能退回一个不可观察的大 Step。Runner 提供受控 `StepGroup`：

- 先由纯函数生成稳定子任务列表。
- 每个子任务具有稳定 `task_id` 和独立 CacheRecord。
- 所有子任务缓存判定完成后，首个真实 miss 才懒加载 provider。
- provider 生命周期归任务组所有，必须 `finally` 关闭。
- OOM/session/provider 故障可在当前任务按既有低预算策略重试；触发批次熔断后后续任务标记 `skipped`，不得继续调用。
- 历史失败记录不成为本轮 warning；本轮真实故障按批次汇总一次。
- 云端子任务必须继续共享单视频请求预算，不得因拆 Step 绕过 `max_calls_per_video`。

### 3.6 Application 与 Desktop 合同

`ProcessingService` 是 Desktop/CLI 与执行内核之间的用例边界：

```python
class ProcessingService(Protocol):
    def cached_result(self, video: Path) -> ProcessingResult | None: ...
    def process(self, request: ProcessingRequest) -> ProcessingHandle: ...
    def aggregate(self, request: AggregateRequest) -> ProcessingResult: ...
    def delete_video_workspace(self, video: Path) -> None: ...
    def clear_workspace(self) -> int: ...
```

约束：

- `ProcessingRequest` 取代 Desktop/CLI 临时拼接的 `qwen_settings/asr_settings/force_*` 可变字典；兼容门面只负责把旧参数翻译为请求 DTO。
- `CloudAuthorization` 明确记录“本次请求已由用户授权”、允许发送的数据类型、候选模型和预算；没有授权对象时 Application 层不得构造 CloudPort。
- `ProcessingHandle` 暴露 cancel、状态订阅和最终结果，不暴露 Thread、Runner、Context 或 provider。
- `ProcessingResult` 是不可变公开 DTO，包含现有公开结果字段，不让 View 读取 Manifest/document 内部 JSON。

Desktop Controller 使用显式状态机：

```text
idle → preparing → running → cancelling → cancelled
                         └──→ completed
                         └──→ failed
```

聚合是 completed items 上的独立 command，不混入单视频 Step 状态。

- Controller 拥有队列选择、当前 item、命令互斥、取消句柄和 UI 状态转换。
- View 只负责控件、对话框和展示；它通过 controller command 输入，通过 `UiEvent` 输出更新。
- 后台线程不得直接调用 Tk；所有 UI 更新必须由 View 使用 `root.after`/主线程 dispatcher 消费。
- Controller/ProcessingService 发布结构化进度，View 才决定中文显示格式；领域事件不得携带 Tk 变量。
- `EtaEstimator` 属于 processing session/controller，不再放进 View 的 QueueItem。
- 文件选择、messagebox、`os.startfile` 属于 View/Windows 平台边界；处理用例不得调用。
- API 设置校验和秘密保存经 `desktop/settings.py` 的窄接口完成，秘密不进入 Controller 状态、repr、日志或 DTO。

## 4. Artifact 与 Workspace 合同

### 4.1 责任拆分

- `WorkspaceLayout`：一个视频 Workspace 的唯一标准路径表。
- `WorkspaceCatalog`：按 source path/video_id 查找 Workspace、列举和安全清理；Desktop、Aggregate、Localplay 不再自行 glob/拼路径。
- `ArtifactStore`：Artifact 读取、Schema 验证、原子 staging/commit、摘要和兼容读取。
- `WorkspaceCache`：Step 指纹、CacheRecord、命中判定和失效原因；不实现领域算法。

不得把上述职责全部塞入一个新的 `WorkspaceCache` 上帝对象。

### 4.2 标准 Artifact

| ArtifactId | 目标路径 | 生产者 | 核心校验 |
|---|---|---|---|
| `source.manifest` | `manifest.json` | `source.probe` | video_id、source、fingerprint、duration |
| `audio.flac` | `audio/audio.flac` | `audio.extract` | 文件存在、非空、来源指纹匹配 |
| `transcript.raw` | `transcript/raw.json` | `transcript.decode` | engine、segments、原始时间范围 |
| `transcript.normalized` | `transcript/transcript.json` | `transcript.normalize` | segment ID、真实时长边界、纠正规则版本 |
| `transcript.srt` | `transcript/transcript.srt` | `transcript.normalize` | 与 normalized segments 同源 |
| `frames.candidates` | `images/candidates.json` + `images/candidates/` | `frames.candidates` | 采样参数、候选清单、文件完整性 |
| `frames.selected` | `images/keyframes.json` + `images/selected/` | `frames.select` | 选择参数、时间戳、文件完整性 |
| `knowledge.plan` | `knowledge/lesson-plan.json` | `knowledge.plan` | plan/unit/source ID 合法 |
| `visual.jobs` | `knowledge/visual-jobs/index.json` | `visual.jobs` | 稳定任务 ID 和候选引用 |
| `visual.evidence` | `knowledge/visual-evidence.json` | `visual.evidence` | VisualEvidence Schema、真实图片引用 |
| `frames.semantics` | `knowledge/frame-semantics.json` | `frames.semantics` | frame/transcript 指纹 |
| `knowledge.course_ir` | `knowledge/course-ir.json` | `knowledge.course_ir` | Claim owner、source/unit/visual ID |
| `knowledge.units` | `knowledge/knowledge-units.json` | `knowledge.units` | plan coverage、content_blocks |
| `knowledge.selfcheck` | `knowledge/selfcheck.json` | `knowledge.selfcheck` | 报告 Schema 与输入指纹 |
| `document.v2` | `knowledge/document.json` | `document.assemble` | Schema v2、content_blocks、source URL |
| `render.markdown` | `output/<video_id>/<title>.md` | `render.markdown` | 文件存在、来源链接和图片引用 |
| `render.word` | `output/<video_id>/<title>.docx` | `render.word` | ZIP/OOXML 可打开、来源链接存在 |
| `render.pdf` | `output/<video_id>/<title>.pdf` | `render.pdf` | PDF 可解析、页数大于零 |

### 4.3 原子写入

- JSON 先写 Step staging，再解析/校验，再 `replace`。
- 多文件 Artifact（帧目录、渲染包）先在独立 staging 目录完成，校验后整体切换；不得先清空有效目录再执行。
- 失败、取消、进程退出和 Schema 不合格时清理本次 staging，不删除上一份有效产物。
- CacheRecord 必须最后提交；出现 Artifact 存在但无成功记录时，按 legacy/adoption 规则处理，不默认命中。

### 4.4 CacheRecord

每个 Step 记录到：

```text
workspace/<video_id>/state/cache/<step_id>.json
```

至少包含：

```json
{
  "schema_version": 1,
  "step_id": "knowledge.units",
  "implementation_version": 1,
  "contract_version": "document-v2",
  "cache_key": "sha256:...",
  "input_components": {},
  "outputs": [],
  "requested_capability": "offline",
  "produced_capability": "offline",
  "status": "succeeded",
  "run_id": "...",
  "created_at": "..."
}
```

不得记录秘密、完整环境变量、请求头、供应商原始响应或与缓存无关的整份配置。

### 4.5 统一命中原因

`CacheDecision` 只能使用稳定 reason code：

- `CACHE_HIT`
- `NO_RECORD`
- `FORCED`
- `STEP_VERSION_CHANGED`
- `CONTRACT_CHANGED`
- `UPSTREAM_CHANGED`
- `CONFIG_CHANGED`
- `CAPABILITY_INSUFFICIENT`
- `OUTPUT_MISSING`
- `OUTPUT_CORRUPT`
- `PREVIOUS_RUN_INCOMPLETE`
- `LEGACY_ADOPTED`

miss 必须携带 `changed_components`，例如 `frames.scene_change_threshold`，让 Agent 不用重新阅读签名实现。

### 4.6 旧 Workspace 认领

- 增加单向 `LegacyArtifactAdapter`，只负责读取和验证旧路径，不包含新业务逻辑。
- 旧 `transcript.json` 若有 `raw_text`，可重建 `raw.json`；无法可靠恢复时保持 normalized Artifact，有需要时仅重跑 decode 下游，不删除旧文件。
- 旧 document v1 通过只读迁移生成内存中的 v2，再由新路径持久化 v2。
- 能证明有效的旧 Artifact 写入 `LEGACY_ADOPTED` 记录，避免无理由重跑 ASR/VLM/云端。
- Adapter 必须有删除条件和目标阶段；不得成为永久第二缓存实现。

### 4.7 Workspace 运行状态

```text
workspace/<video_id>/state/
├── pipeline-state.json
├── cache/<step_id>.json
├── runs/<run_id>.jsonl
└── staging/<run_id>/<step_id>/
```

- `pipeline-state.json` 是当前执行真相；Manifest 只保留来源信息和向后兼容的阶段摘要。
- 运行事件使用 JSONL 追加，避免当前每条事件重写整个 `runtime-events.json`。
- 确认没有生产读取方后停止生成新的 `runtime-events.json`；历史文件不主动删除。
- 增加单视频 Workspace lease，避免 Desktop 与 CLI 同时处理同一视频；锁包含 PID、run_id 和创建时间，支持安全识别陈旧锁。

## 5. 工程中间件解耦

### 5.1 端口

在 `execution/ports.py` 定义最小 Protocol：

- `MediaPort`：probe、extract_audio、extract_frame_candidates。
- `SpeechPort`：probe capability、decode；术语/时间规范化不放进 provider。
- `VisionPort` / `VisionSession`：preflight、open session、compare、detail、close。
- `CloudJsonPort`：受共享预算控制的 JSON 请求；业务层提供 payload 和 validator。
- `DocumentPort`：render markdown、render word、convert/render PDF。
- `ProcessPort`：可取消、可超时的本地命令，仅基础设施 adapter 使用。

### 5.2 唯一 composition root

`execution/bootstrap.py` 是唯一连接具体实现的位置：

- 读取已编译配置。
- 构造 Context 和 RuntimeServices。
- 创建 lazy provider factory。
- 注册内置 Step。
- 返回 PipelineRunner/ProcessingService。

Step、领域模块和 Desktop 不得自行 new `FallbackChatClient`、VLM provider、OpenAI SDK 或 subprocess runner。

### 5.3 懒加载和资源生命周期

- Cache 判定完成前不得调用 ASR/VLM/Cloud/Word adapter 的 preflight 或构造昂贵对象。
- VLM session 归 `visual.evidence` 任务组，单视频真实 miss 首次出现才加载，整个任务组只加载一次。
- CloudRequestBudget 归单视频 Context，planning/organizing/重试/降级共享同一对象。
- 子进程都经统一取消/超时/终止策略，错误映射到稳定 error code；领域层不解析 `CalledProcessError`。
- Word 不可用或超时时按现有策略静默切到内置 PDF；这属于 adapter 内的合法实现选择，不成为业务 warning。

### 5.4 中间件边界自动测试

- AST 测试限制 `subprocess` 只出现在批准的基础设施模块和 runner 脚本。
- AST 测试限制 `openai` 只由 cloud adapter 导入。
- Step 使用 fake ports 完成测试，不依赖真实模型、ffmpeg、Node、Word 或网络。
- 全缓存命中测试断言所有 provider factory 调用次数为 `0`。
- 取消测试断言已启动的子进程被关闭且无新 CacheRecord。

## 6. 目标 Step DAG

```text
source.probe
├── audio.extract → transcript.decode → transcript.normalize
└── frames.candidates

transcript.normalize + frames.candidates
    → frames.select

transcript.normalize
    → knowledge.plan

knowledge.plan + frames.select + transcript.normalize
    → visual.jobs → visual.evidence

frames.select + transcript.normalize
    → frames.semantics

knowledge.plan + transcript.normalize + visual.evidence
    → knowledge.course_ir

knowledge.plan + knowledge.course_ir + frames.semantics + visual.evidence
    → knowledge.units → knowledge.selfcheck

knowledge.units + knowledge.selfcheck + visual.evidence
    → document.assemble

document.assemble
├── render.markdown
└── render.word → render.pdf
          document.assemble ───────┘（内置 PDF fallback 需要）
```

### 6.1 选择性失效矩阵

| 变化 | 必须重跑 | 不得重跑 |
|---|---|---|
| 视频来源指纹变化 | 全部下游 | 无 |
| ASR engine/model/解码参数 | transcript.decode 及下游 | audio.extract |
| 术语规则/时间规范化规则 | transcript.normalize 及下游 | audio、decode |
| 帧采样间隔/宽度 | frames.candidates、select、视觉、document、render | audio、transcript、无关 plan（若 plan 不依赖帧） |
| 帧选择阈值/内容起点 | frames.select、视觉、document、render | candidates、ASR |
