## 0. 给执行 Agent 的结论

本轮不是“继续叠模型”，也不是把现有 VLM 调用简单改成并行 batch。六个问题来自同一条数据链，但必须按依赖顺序收敛：

```text
P0 基线与开关
→ P1 CourseIR 影子层、Claim 唯一所有权和确定性去重
→ P2 视觉任务收敛、场景预占和单会话 VLM
→ P3 紧凑 CloudPayload 与请求前分批
→ P4 Canonical Document v2 迁移
→ P5 任务型 ETA 与桌面状态
→ P6 默认切换和一次性验收
```

不得一次性同时改完所有合同后再测试。每阶段达到本文的“收敛门”后再进入下一阶段；未通过时只修当前阶段或走其直接回滚路径。

本轮目标：

1. 消除讲义中同一句话在标题、正文、规则和步骤中的重复展示。
2. 视觉调用从“每题启动并加载模型”变为“每视频加载一次、任务顺序执行并逐项缓存”。
3. 将正常无图可选与真实推理故障分开，最多生成一条任务级故障 warning。
4. 云端只接收紧凑、可校验的 CourseIR 投影，不接收 Markdown、PDF、完整 `document.json` 或默认图片像素。
5. ETA 按真实任务单元估算，无依据时诚实显示“估算中”。
6. 保持桌面产品边界、来源时间戳、`video-study://` 和 JSON → Markdown → Word → PDF 链路。

P1 先在内部建立权威结构，仍由 adapter 输出 schema v1；不能在这一阶段顺手切 Document v2。

### 修改范围

### 最小接口

```python
build_source_blocks(transcript) -> list[SourceBlock]
build_course_ir(lesson_plan, transcript, visual_evidence) -> CourseIR
course_ir_to_units(course_ir, content_level) -> list[KnowledgeUnit]
route_claims_to_blocks(claims) -> list[ContentBlock]
validate_title(title, body) -> TitleValidation
run_dedup_gate(units) -> tuple[list[KnowledgeUnit], DedupReport]
```

### 数据约束

- `SourceBlock` 保留稳定 source/segment ID、起止时间、原始文本和可选复述标记；原始 transcript/SRT 不改不删。
- `Claim` 至少有稳定 ID、unit ID、kind、text、source IDs、origin 和 fingerprint。
- `origin` 明确区分 `audio_backed`、`visual_backed`、`model_aid`；模型帮助理解不得伪装成课堂事实。
- 每个 Claim 只有一个主要展示位置：paragraph、rule_list、steps、example、pitfall、visual_group 或 understanding_tip。
- planning 和 organizing 复用同一个 SourceBlock builder，继续保持现有 `block_0001` 等映射稳定。

### 去重边界

第一版仅自动处理：

1. 同 block 完全重复：保留一条并合并来源。
2. list item 被 paragraph 完整包含：按 Claim 类型选择一个展示位置。
3. 标题与正文开头高度重合：改标题，不能删正文证据。

近重复只报告，不自动合并。任何数字、百分比、时间、否定词、条件词、例外词或来源不同，都视为可能新增信息。禁止跨主题自动合并。

`selfcheck` 在现有质量报告内增加：

- `duplicate_claim_count`
- `containment_duplicate_count`
- `title_body_overlap_count`
- `near_duplicate_pairs`
- `claims_without_source`

不要创建第二套独立“质量门系统”。

### 收敛门

- 同一 Claim 不再同时出现在 paragraph 与 rule_list/steps。
- 包含新增数字、否定、条件、例外的相似句全部保留。
- 来源覆盖率、时间回看链接和知识点核心结论不低于基线。
- adapter 仍可输出 schema v1；Markdown、Word、PDF 现有消费者无需先重写。
- 只有达到本门，才允许进入视觉会话或 Document v2。

### P2.2 单会话 runner

修改：

- `src/video_study/knowledge/vision_providers.py`
- `scripts/qwen_vl_runner.py`
- `src/video_study/knowledge/visual_retrieval.py`
- 对应 provider/runner/retrieval 单测

建议实现一个视频级 `QwenVLSession`，不要建立常驻服务：

1. 使用 `D:/Anaconda/envs/envs/ImageT10/python.exe -u scripts/qwen_vl_runner.py --session ...` 启动一次短生命周期子进程。
2. runner 首先将 `models/qwen3-asr-runtime` 插入 `sys.path`，再导入 torch/transformers，并以 `local_files_only` 加载 `models/qwen3-vl-2b-instruct`。
3. 优先使用临时 jobs 目录的原子文件协议，规避 Windows PIPE 缓冲区死锁：父进程写 `request.tmp` 后 replace 为 request；runner 写 `result.tmp` 后 replace 为 result；每项带唯一 `job_id`。
4. runner 模型加载完成后写 `ready.json`；每个 job 完成即在任务 workspace 的 `knowledge/visual-jobs/` 落盘，正常 `no_match` 也缓存。
5. compare 完成后可动态提交 detail；所以 job 顺序执行，`micro_batch_size=1`。
6. 当前 runner 每次结果后使用 `os._exit(0)` 规避 Windows/CUDA 析构卡死。会话模式不能每 job 退出；只允许在最终 `done` 和最后结果已原子写完、文件已 flush 后结束进程。
7. stdout/stderr 仅作诊断，但父进程仍需持续排空；统一 UTF-8（`PYTHONIOENCODING=utf-8`、`PYTHONUTF8=1`）。
8. 取消/超时使用 Windows 进程树终止路径（`taskkill /PID <pid> /T /F` 或现有等价封装），并确认子进程退出和显存释放；不能只依赖 Unix signal。
9. session 崩溃最多重启一次，只提交未完成的 transient jobs；已完成 job 不重跑。保留 `per_call` 作为直接回滚。

禁止在 ASR、VLM、Word COM 之间并发；同一任务 manifest 也保持串行写入。

### P2.3 三态结果与告警

统一分类：

| 状态 | 范围 | 用户表现 |
|---|---|---|
| `expected_no_match` | 合同拒绝、候选不足、criteria 不满足、场景占用 | info，任务正常完成 |
| `recovered_quality` | detail 失败但 compare 已有完整证据 | info，保留可靠证据 |
| `inference_failure` | timeout、OOM 重试失败、runner 崩溃、协议非法 | 整个任务最多一条汇总 warning |

当前正常 `no_match` 误报已有修复，不要推倒重写。只补合同拒绝、`auto` 能力缺失、会话故障聚合和版本指纹。`local_vlm_enabled=auto` 但能力不存在时只提示一次 info；用户显式要求 VLM 而能力不可用时才 warning。

### P2 总收敛门

- fake 多 job 会话中 `_load_model()` 恰好一次。
- compare ≤8、detail ≤2，且场景在推理前去重。
- 模拟中途崩溃后已完成 job 不重跑；取消后无残留进程。
- 多个真实推理错误只形成一个任务 warning；正常拒绝为 info。
- `per_call` 回滚路径仍通过相关单测。

plan_payload_batches(payload, max_input_chars, max_output_tokens) -> list[PayloadBatch]

```

### 载荷合同

- 使用紧凑但可读的 JSON 字段；只传当前 unit/batch 实际引用的 sources、units、必要 claims 和 selected visuals。
- visual 只传 `visual_id`、`unit_id`、`role`、`facts`、`answer`；云端只能返回这些 ID 的放置位置和文字组织。
- 禁止本地 path、base64、图片 hash、设备/runtime、缓存签名、no_match、Markdown、PDF、DOCX 和完整 `document.json`。
- 有 selected VisualEvidence 后，不再同时发送完整 FrameSemantic；OCR 仅在不与 facts 重复且有教学价值时进入事实字段。
- 请求前计算整篇或分章批次。超预算时整篇 client 调用次数必须为 0，不能先发送失败再回退。
- 云端返回的 source/unit/claim/visual ID 必须属于允许集合；集合外 ID 确定性失败，不允许猜测映射。
- `CloudPayloadError` 必须结束云端阶段并保留本地产物，不能落入旧 `_qwen_summary()`。

保存 `workspace/.../cloud-payload.json` 作为本地审计 artifact，可记录 chars、批次数、source/unit/visual 数量，但不得包含密钥。Markdown/PDF 继续只作为最终输出。

### 收敛门

- 固定 fixture 的 payload 字符量不高于旧 organizing 动态上下文的 60%。这是离线字符门，不伪装成精确 token 数。
- 超预算测试中整篇 client 调用次数为 0；payload 构造/响应校验失败时所有云端 mock 调用次数为 0。
- 禁止字段快照检查通过，所有引用 ID 有效。
- 没有新的用户授权时，到此即完成 P3 验证，不将“未做真实云端”视为失败。

ProgressEvent(stage, unit_kind, completed, total, cache_hit, duration_seconds)
EtaEstimator.observe(event)
EtaEstimator.estimate() -> float | None
```

### 规则

- 删除桌面端 `elapsed * (100 - progress) / progress` 的线性 ETA。
- ASR 按音频秒数，frames 按候选数，visual 按 cold load/compare/detail job，cloud 按 planning/organizing batch，render 按 Markdown/Word/PDF 子阶段上报。
- VLM cold load 与 warm job 分开统计；warm job 使用最近 5 项中位数，历史最多保存 20 组。
- 历史只保存硬件、模型、档位、缓存状态和耗时，不保存视频名、转写、图片或密钥。
- 没有足够样本时返回 `None`，UI 显示“估算中”。有估算后保存 monotonic deadline，`_tick()` 每秒倒计时。
- job 数变化、缓存命中和阶段完成时重算；取消后清空 ETA。
- `auto` 明确为 `local_prepare` 与 `cloud_refine` 两阶段，不再机械拆成 50/50；本阶段不改变 `auto` 的业务语义。

### 收敛门

- 无历史不显示伪剩余时间。
- warm job 到达后 ETA 随 deadline 每秒下降，并能在任务总数变化时校正。
- cache hit 不沿用未命中耗时；取消后 ETA 立即清空。
- 回滚只显示“—/估算中”，不恢复旧公式。

## 12. 硬停止与降级条件

遇到以下任一条件，不得现场扩环境或增加技术堆叠：

### 环境

- preflight 路径缺失、`model_complete=false`、CUDA 不可用，或实际 import 未落到 torch 2.7.1+cu128 / transformers 5.14.1：停止真实视觉，离线功能继续。
- 真实验收前 GPU free <6.0 GiB、系统 RAM free <3 GiB 或 D 盘 free <15 GiB：延后重资源验收。
- 不要再次验证 ImageT10 原生 Qwen3-VL import；其失败原因已明确。

### 视觉会话

- 同一会话 `_load_model()` >1、ASR/VLM 重叠、job 未原子缓存，或取消后 5 秒仍有子进程/显存未释放：停止性能验收，回滚 `per_call`。
- OOM、显存接近 7.6 GiB、单 job 达到现有 55 秒生成上限：终止真实测试；先减候选和视觉 token，不加并发、量化或 CPU offload。

### 正文与载荷

- 去重丢失数字、否定、条件、例外或来源：关闭 near-duplicate 自动动作，只保留 exact + containment。
- compact payload 出现非法 ID、来源覆盖下降或模型遵约率退化：不发云端；保留可读字段名，不用晦涩缩写换 token。
- CourseIR/CloudPayload 构造失败：本地产物正常交付，云端状态明确为未发送；禁止旧 prompt 回退。
