## 开工读取顺序

1. `MEMORY.md`。
2. `迭代升级/AI执行入口.md`。
3. `迭代升级/当前架构升级状态.yaml`；P0 尚未创建时直接进入主清单 P0。
4. 主清单第 0 节。
5. 只读当前 Phase 及下表列出的合同章节；不要预读后续 Phase 的实施细节。

不要每轮重读完整主清单、完整执行事实或全部历史任务书。只有需要追溯已验证行为时，才按 AI执行入口指定键读取 `执行事实.yaml`。

## 执行纪律

- 一次只执行一个 Phase；阶段内可按工作包小步提交修改，但不得并行维护两套生产实现。
- 先写/固定失败测试，再修改责任模块。
- 每个 Phase 先跑直接影响测试，达到收敛门后跑一次完整离线测试。
- Artifact、Step ID、错误码或依赖方向与合同冲突时，按合同变更规则暂停并请求决策；普通实现不更新稳定合同。
- 真实云端调用默认 0 次；任何真实调用都重新取得用户授权。
- 当前状态文件只记录完成项、阻塞、下一步和测试摘要，不复制调查过程。
- 用户版本时间线 V4.0 已批准并记录；后续实施状态不得再次追加 V4.0 时间线条目。

## 交付判断

只有主清单 P0–P11 全部达到各自收敛门，且 P11 完成，才能将 V4.0 标记为实施完成。仅创建新抽象、仅切换 Runner、仅拆分 Desktop 或仅通过单元测试，都不等于 V4.0 完成交付。
