# 知识整理升级实施任务书

更新时间：2026-08-06

## 1. 任务目标

在不破坏现有原生 Windows 桌面产品和可恢复数据流的前提下，把当前“一条通用提示词直接生成全文”升级为：

```text
转写与候选画面
→ 课程画像
→ 知识内容鉴别与选择
→ 按知识类型专业化整理
→ 轻量自检
→ JSON → Markdown → Word → PDF
```

本轮重点是知识鉴别、篇幅选择和专业化呈现，不是更换 UI 框架，也不是单纯加长提示词。

## 2. 已确认的产品判断

1. 用户提供的整理文档是偏好样本，不是知识标准答案。
2. 需要学习的是用户的思考方式：核心内容详细、旁支简写或只留索引、规则按条件和例外展开、图片服务于理解。
3. 自动适配不能只有领域分类，还要识别课程形态、知识类型和内容角色。
4. 领域信息只用于选择术语、结构和整理策略；不得默认补充视频之外的事实。
5. 不建设依赖大量人工样本或额外模型调用的重型质量门，只做低成本防错与人工抽查。
6. 云端仍然显式授权；不默认上传视频或截图。视觉模型如需引入必须另行 opt-in。

## 3. 必须保留的现有能力

- 唯一产品入口仍是原生桌面程序，不增加 Web UI、本机 HTTP 服务、端口监听或 `serve` 命令。
- 视频使用用户选择的绝对路径，不复制、不上传。
- 保留可恢复的 JSON → Markdown → Word → PDF 链路。
- 保留每条知识的时间戳与 `video-study://play/<video_id>?t=<seconds>` 本地回看。
- 保留 ASR、候选帧和已完成阶段缓存；只变更知识整理时不得重跑长视频 ASR 或抽帧。
- 保留精简、推荐、丰富三个用户入口，但允许它们映射到新的内容选择策略。
- 保留多模型降级、取消、进度和 Token 统计。

## 4. 建议的最小数据结构

先引入两个中间结构，不急于一次完成长期 schema。

### 4.1 ContentDecision

```json
{
  "decision_id": "decision_0001",
  "source_segment_ids": ["segment_0001"],
  "role_tags": ["core"],
  "knowledge_types": ["rule"],
  "importance": "core",
  "keep_mode": "expand",
  "confidence": 0.92,
  "reason": "后续多个案例重复使用该判定条件"
}
```

建议枚举：

- `role_tags`：`core`、`supporting`、`boundary`、`navigation`、`time_sensitive_tangent`、`noise`、`uncertain`。
- `knowledge_types`：`concept`、`rule`、`procedure`、`mechanism`、`comparison`、`case`、`boundary_case`、`visual_or_formula`、`conclusion`。
- `keep_mode`：`expand`、`concise`、`index_only`、`omit`。

分类允许多标签。低置信度内容不得直接丢弃，应回退为 `concise` 或 `uncertain`。

### 4.2 KnowledgeUnit

```json
{
  "unit_id": "unit_0001",
  "type": "rule",
  "title": "规则标题",
  "importance": "core",
  "definition_or_conclusion": "忠于来源的定义或结论",
  "prerequisites": [],
  "branches": [],
  "procedure": [],
  "rules": [],
  "exceptions": [],
  "positive_examples": [],
  "negative_examples": [],
  "pitfalls": [],
  "unresolved": [],
  "evidence_refs": []
}
```

第一版可以允许部分字段为空，但不得为了填满 schema 而生成来源没有的内容。

## 5. 知识鉴别策略

### 5.1 全局判断

先根据文件名、压缩转写、重复术语和已有画面元数据生成轻量课程画像：

- 领域与子领域。
- 课程形态：规则教学、概念讲授、案例复盘、软件演示、会议讨论等。
- 主要知识类型。
- 核心主线和明显旁支。
- 分类置信度。

不要把静态领域词表当作唯一依据。当前配置中的医学 hotwords 不适合金融课程，后续应让课程画像产生本次任务的动态术语提示，但不要立即删除用户已有静态替换规则。

### 5.2 内容选择

- 先看全局主线，再判断局部片段，避免把短小但关键的定义误删。
- 核心知识使用 `expand`。
- 支撑解释和代表性案例根据内容档位使用 `expand` 或 `concise`。
- 时效旁支默认 `concise` 或 `index_only`，除非课程本身就是复盘类。
- 重复口语和宣传使用 `omit`，但选择记录仍保存在中间 JSON 中。
- ASR 不清、前后冲突或依赖缺失画面的内容使用 `uncertain`，保留回看位置。

## 6. 专业化整理策略

不要为每种知识类型单独发起一次 API 请求。把提示词拆成可组合模块：

```text
基础忠实性约束
+ 课程画像与动态术语
+ 用户呈现偏好
+ 当前章节涉及的知识类型模板
```

各类型的主要模板要求：

| 类型 | 重点字段 |
|---|---|
| 概念 | 定义、组成、边界、相近概念区别 |
| 规则 | 前置条件、判断顺序、方向分支、成立/不成立、例外 |
| 流程 | 输入、步骤、停止条件、输出、失败处理 |
| 原理 | 前因、过程、结果、适用范围；禁止补造因果 |
| 对比 | 对比维度、共同点、差异、选择条件 |
| 案例 | 背景、对象、逐步应用、结论、可迁移经验 |
| 反例 | 违反的条件、不成立原因、易错位置 |
| 图表/公式 | 对象、读图顺序、口述对应关系、无法确认部分 |

分类不是不可逆路由。整理阶段发现新类型时允许补标签；低置信度分类退回通用知识单元。

## 7. 调用与缓存建议

- 短视频允许一次请求同时完成鉴别和整理。
- 长视频建议一次全局鉴别，再按 2–4 个语义章节整理；不要切成大量小调用。
- 把“流水线请求次数”和“单次请求的模型降级尝试次数”分开配置，避免复用当前 `max_calls_per_video` 造成语义混乱。
- 新增缓存建议：
  - `knowledge/content-decisions.json`
  - `knowledge/knowledge-units.json`
  - 现有 `knowledge/document.json`
- 缓存签名至少包含转写、画面索引、画像/选择/整理版本、内容档位和来源协议。

## 8. 轻量自检

只实现低成本检查：

- 核心知识至少引用一个真实 segment。
- 结果引用的 segment 和 frame 必须存在。
- 原文中与规则相关的否定、同价、前后、上下等方向表达不能被静默删除。
- 标为 `expand` 的规则如果完全没有条件、步骤或边界，产生提示但不强行编造。
- 同一术语出现明显相反结论时进入 `unresolved`，不自动合并。
- 依赖画面但没有可靠图片时标记“需回看画面确认”。
- 记录展开、简写、仅索引、忽略、待确认的数量，供人工快速抽查。

不要求建立大规模样本集、标准答案或独立评测模型。

## 9. 建议代码落点

第一轮不进行全项目搬家，只创建清晰边界并从 `summarize.py` 中抽离新能力：

```text
src/video_study/knowledge/
  schema.py
  profiling.py
  selection.py
  organizer.py
  selfcheck.py
  prompts/
    base.py 或 base.md
    domains/
    knowledge_types/
```

要求：

- `pipeline.py` 只负责编排，不嵌入提示词。
- 供应商调用继续通过现有 provider 层。
- 旧 `document.json` 读取保持兼容；必要时增加 adapter。
- 聚合优先消费 `KnowledgeUnit`，避免再次把详细内容压成通用摘要。
- UI 第一轮只复用现有内容档位，不增加大量设置控件。

## 10. 推荐实施顺序

1. 定义并测试 `ContentDecision`、`KnowledgeUnit` 及序列化。
2. 把现有云端提示词从 `summarize.py` 拆成可组合模块，保持原行为可回退。
3. 实现课程画像和内容选择，先生成 `content-decisions.json`。
4. 按语义章节生成 `knowledge-units.json`。
5. 用 adapter 生成现有 `document.json`，继续走原渲染链。
6. 增加轻量自检和过程统计。
7. 复用现有三个视频的 ASR/截图缓存做人工抽查；真实云调用前必须再次获得用户授权。
8. 内容链稳定后，再拆 `desktop.py` 和完善本地 OCR/图文对齐。

## 11. 完成条件

- 不重跑已有长视频 ASR 和抽帧即可重新生成知识中间层。
- 核心、旁支、噪声和待确认内容有可追溯的选择记录。
- 至少支持概念、规则、流程、案例、边界五类专业化整理。
- 现有 Markdown、Word、PDF 与本地视频协议继续工作。
- 本地模式、云端 opt-in、取消与缓存恢复不退化。
- 单元测试、compileall、pip check、Node 渲染脚本语法检查和 `git diff --check` 通过。

## 12. 非本轮目标

- 不重写 Tkinter 桌面界面。
- 不引入 Web UI、HTTP 服务或端口监听。
- 不默认调用视觉模型或上传截图。
- 不建设重型评测平台。
- 不引入外部知识库自动扩写课程事实。
