## 1. 总体架构与分层

V6.0 将生产编排器从 `PipelineRunner` 迁移到 **LangGraph**（`GraphRuntime`），成为唯一生产编排器。V6.1 在确定性主图内新增受控的 **EditorialAgentSubgraph**，以阶段限定 Function Calling 赋予 LLM 主动观察和局部编辑权。

系统采用六边形架构，核心原则是**业务逻辑不依赖具体模型/外部服务实现**，所有外部能力通过端口（Port）注入。

```
┌─────────────────────────────────────────────────────────┐
│                     桌面端 (desktop/)                     │
│   DesktopController（状态机） ←→ Tk View（UI 渲染）        │
│              ↓ 只调用 Application Service                  │
├─────────────────────────────────────────────────────────┤
│                   应用层 (application/)                   │
│   ProcessingService · ProcessingRequest · ProcessingHandle│
│              ↓ 调用 GraphRuntime                          │
├─────────────────────────────────────────────────────────┤
│              执行层 (execution/) — V6.0 Graph 内核        │
│   GraphRuntime（唯一编排器）→ NodeExecutor（事务执行）      │
│        → ArtifactStore（原子写入） → WorkspaceCache       │
│        → Graph Checkpoint（同 Job 恢复）                   │
│              ↓ 调度 23 个节点                               │
├─────────────────────────────────────────────────────────┤
│              编辑层 (editorial/) — V6.1                    │
│   EditorialAgentSubgraph · Function Calling 工具          │
│   Blueprint → Chapter Write → Quality Audit → Patch      │
├─────────────────────────────────────────────────────────┤
│              知识子系统 (knowledge/)                     │
│   规划 → 视觉证据 → CourseIR → 整理 → 自检                │
├─────────────────────────────────────────────────────────┤
│                端口与适配器 (ports + adapters)            │
│   MediaPort · SourcePort · SpeechPort · VisionPort        │
│   CloudJsonPort · CloudToolPort · DocumentPort            │
│   —— 具体实现惰性构造，不提前加载模型                       │
└─────────────────────────────────────────────────────────┘
```

### 分层边界（`module-boundaries.yaml` 校验）

| 层 | 模块 | 允许依赖 | 禁止依赖 |
|---|---|---|---|
| 应用层 | `application` | execution, aggregate, config | tkinter, knowledge, openai, subprocess |
| 桌面层 | `desktop` | application, desktop.models, desktop.settings | knowledge, providers, execution.graph_runtime, subprocess, openai |
| 执行层 | `execution` | execution, progress | tkinter, openai, subprocess |
| 编辑层 | `editorial` | execution, knowledge | desktop, openai, subprocess |
| 知识层 | `knowledge` | knowledge, transcript, execution.task_groups | desktop, pipeline, tkinter, subprocess, openai |
| 端口层 | `execution.ports` | execution.contracts | desktop, tkinter |
| 渲染层 | `render` | document.v3, document.v2.read_adapter, localplay | desktop, providers, knowledge.planning, openai |
| 源获取层 | `source` | runtime, utils | desktop, knowledge, openai, tkinter |

### 组合根

`execution/bootstrap.py` 中的 `build_runtime_services` 是唯一依赖注入点：

- 所有 Port 工厂注册为**惰性单例**（`RuntimeServices.port(name)` 首次调用时构造，线程锁保护）。
- `cloud` Port **仅在** `RunPolicy.cloud_authorized=True` 时注册；未授权时构造和请求均为 0。
- `cloud_tool` Port（V6.1）仅在模型能力门禁通过 `tool_native` 或 `structured_only` 时注册。
- `vision` Port 在 `open_session` 时才执行预检（preflight），预检失败不阻塞流水线。
- `source` Port 在 `config.source.enabled=true` 时注册（V5.0）。
- `LocalDecisionPolicy` 不依赖 LLM，负责路由/降级/缓存决策，即使所有模型初始化失败仍能生成完整文档。

## 2. Graph 编排与节点详解

### 2.1 Graph 拓扑

```text
JobGraph
├─ SourceGraph
│  ├─ local.resolve
│  └─ url.preflight → url.acquire → source.verify
├─ VideoGraph × N（按队列顺序，避免多视频争抢 GPU/磁盘）
│  ├─ source.probe → audio.extract
│  ├─ transcript.decode → transcript.normalize
│  ├─ frames.candidates → frames.select
│  ├─ knowledge.plan → visual.jobs → visual.evidence → frames.semantics
│  ├─ knowledge.course_ir → knowledge.units → knowledge.selfcheck
│  ├─ editorial.policy → evidence.reconcile
│  ├─ EditorialAgentSubgraph（V6.1）
│  │   blueprint.agent → blueprint.validate/commit
│  │   → chapter.write[N] → document.assemble
│  │   → preview.render → quality.audit
│  │   → revision.agent? → patch.validate/apply?
│  │   → editorial.finalize
│  ├─ document.compile → document.validate
│  └─ render.markdown → render.word → render.pdf → render.verify
├─ AggregateGraph（aggregate_mode != none 时）
└─ job.finalize
```

### 2.2 NodeExecutor 事务合同

`NodeExecutor` 是无调度职责的事务执行器，所有产生副作用的节点统一调用：

```
cancel check
→ resolve and validate input ArtifactRefs
→ compute fingerprint
→ cache decide / cache-hit validate
→ acquire workspace and resource leases
→ create staging
→ execute node port/domain function
→ validate NodeOutcome and output contracts
→ atomically commit Artifacts
→ record WorkspaceCache
→ emit committed terminal event
→ return State delta
→ LangGraph writes next checkpoint
```

强制规则：
- 缓存判定完成前不得初始化 ASR/VLM/云客户端/Word 等昂贵端口。
- Node 只能写自己的 staging 和声明输出；不得直接改写其他节点 Artifact。
- Artifact 提交先于 CacheRecord，CacheRecord 先于 Node 返回。
- 所有副作用必须幂等，重放不得重复产生云成本或覆盖有效产物。

崩溃恢复：

| 崩溃位置 | 恢复行为 |
|---|---|
| 提交前 | 正式产物不变；清理 staging 后重跑 |
| Artifact 提交后、缓存前 | 验证孤立 Artifact，满足合同则单向认领，否则重跑 |
| 缓存后、Checkpoint 前 | 缓存命中后返回相同引用，不重复模型调用 |
| Checkpoint 后 | 从下一待执行节点恢复 |

### 2.3 源获取（V5.0，保持不变）

URL 链接源经 `SourceGraph` 处理：`SourcePort.preflight(url)` → yt-dlp `-J` 预检映射 `SOURCE_*` 错误码 → `WorkspaceCatalog.find_by_url` 缓存命中 → `SourcePort.acquire` 下载（清晰度降级链 ≤1080P→720P→480P→360P）→ ffprobe 时长校验 → 以本地文件复用后续节点。

### 2.4 媒体探测与提取

与 V5.1 一致：`source.probe`（ffprobe 探测）→ `audio.extract`（16kHz FLAC）→ `transcript.decode`（引擎链回退）→ `transcript.normalize`（钳制时间戳 + 术语纠正）→ `frames.candidates`（600 帧采样）→ `frames.select`（场景聚类 + 熵选择）。

### 2.5 知识整理

`knowledge.plan` → `visual.jobs` → `visual.evidence` → `frames.semantics` → `knowledge.course_ir` → `knowledge.units` → `knowledge.selfcheck`。

V6.0 修复：`visual.jobs` 和 `visual.evidence` 消费完整候选池（~600 帧 `frames.candidates`）而非仅全局已选 8 帧（`frames.selected`），修复视觉检索输入合同问题。视觉需求分级为 `none/supportive/required`。

### 2.6 EditorialAgentSubgraph（V6.1）

V6.1 在 `knowledge.selfcheck` 与 `document.compile` 之间替换旧伪规划/机械章节链，引入显式 LangGraph 子图。详见 [§7 云端预算与 Function Calling](#7-云端预算与-function-calling)。

### 2.7 渲染（V6.1 原生 v3.1）

`render.markdown` / `render.word` / `render.pdf` 直接消费 Document v3.1 组件树：
- **Markdown**：`render_v31.py:render_markdown_v31` 遍历组件树。
- **Word**：`scripts/render_docx_v31.mjs` 遍历 v3.1，公式生成 OMML（docx 9.7.1 Math → `<m:oMath>`）。
- **PDF**：优先由 Word 转换或直接消费同一组件树。
- **生产不再 `v3_to_v2`**；旧 v2 渲染器只读兼容。

## 3. 各模型工作方式与模块边界

### 3.1 ASR — 语音识别

V4.2 升级后的双引擎链（faster-whisper + Qwen3-ASR），含结构化事件、设备动态适配和 RTF 熔断。详见开发文档 SpeechPort 段落。

### 3.2 VLM — 视觉语言模型

Qwen3-VL-2B-Instruct，单视频单会话。V6.0 修复视觉检索输入合同（消费完整候选池）。V6.1 中本地 VLM 可参与页面审计（`local_vlm` 角色），但页面截图不上传云端。

### 3.3 Cloud LLM — 云端大语言模型

| 维度 | 值 |
|------|------|
| 协议 | OpenAI 兼容 API |
| 模型链 | `glm-5.2`（默认首位，tool_native）→ `deepseek-v4-flash-0731` → `kimi-k2.6` → `qwen3.7-plus` |
| 预算控制 | `CloudRequestBudget`（V6.0）+ `StageBudget`（V6.1，分阶段限制调用/Token/工具轮次） |
| 构造门控 | `bootstrap.py` 仅在 `cloud_authorized=True` 时注册 cloud Port 工厂 |

V6.1 新增 `CloudToolPort`：`invoke_turn(messages, tools, tool_choice, stage, budget, cancel_check) → ToolTurn`。`ToolTurn` 只包含 `content/tool_calls/invalid_tool_calls/model/attempts/usage/finish_reason/safe_error_code`，不包含密钥、请求头或完整供应商响应。

### 3.4 编辑意图系统（V6.1）

`EditorialPolicy`（V6.1）从用户自然语言编译为 `required/preferred/forbidden` 约束，替代旧 `EditorialBrief`。`LocalIntentCompiler` 提供保守本地回退。`DocumentBlueprint v2` 不含旧 `source_section`，由 LLM 在渲染能力范围内自主规划章节、组件、详略和布局。

## 4. 模态融合机制

V6.0 保留了 V5.1 的 7 个模态融合点（帧选择对齐 → 视觉需求生成 → 视觉任务构建 → VLM 像素核验 → CourseIR 整合 → 知识单元组装 → 文档溯源），并修复了视觉检索输入合同问题（消费完整候选池）。V6.1 新增第 8 个融合点：

### 4.8 融合点 8：编辑 Harness 证据查询（V6.1）

EditorialAgentSubgraph 中的 `lookup_evidence` 和 `lookup_visual_facts` 工具让 LLM 在规划文档时主动查询转写段和视觉事实，实现音频/视觉/编辑意图的三方融合。LLM 收到的是有界来源段和视觉事实摘要（不含图片数据），输出的是重组后的 DocumentBlueprint/Chapter/Patch。

## 5. 失败降级全路径

### 5.1 ASR 降级（V4.2）

引擎链回退 + 设备动态适配 + RTF 熔断，与 V5.1 一致。

### 5.2 VLM 降级

与 V5.1 一致：`auto` 模式预检失败静默降级到 OCR-only；OOM 重试 2 帧；会话失败重启一次后批次熔断。

### 5.3 云端知识降级（V6.0）

`cloud_authorized=false` → 全部离线。`cloud_authorized=true` 时，各节点 cloud 调用失败回退离线，标记 `DEGRADED`。降级产出仍为有效 Artifact；下次运行若仍 `cloud_authorized=True`，cache 返回 `CAPABILITY_INSUFFICIENT` 自动重跑。

### 5.4 Function Calling 三级降级（V6.1）

```
模型能力门禁检测
  │
  ├─ tool_native（模型稳定返回标准 tool_calls）
  │   └─ 完整 EditorialAgentSubgraph（观察+提交+修订）
  │
  ├─ structured_only（模型不支持工具/连续非法 tool call）
  │   └─ 强制结构化输出，无观察循环，云端正文仍可用
  │   └─ 记录 editor_mode=structured_cloud
  │
  └─ local_deterministic（未授权/熔断/所有模型失败/预算耗尽）
      └─ 不构造 CloudPort，运行完整本地语义编译链
      └─ 标记 degraded（除非用户选择本地且质量门全通过）
```

### 5.5 渲染降级

PDF：优先 Word COM → reportlab 回退。V6.1：Word 公式优先 OMML → 降级为矢量/位图公式并保留语义源。

### 5.6 降级状态流转

| 终态 | 含义 | 产物 | 缓存 |
|------|------|------|------|
| `succeeded` | 必需 Artifact 和全部硬质量门通过 | 完整 | 记录 |
| `degraded` | 产物完整，但模型/视觉/公式/意图等增强局部降级 | 完整可用 | 记录 |
| `failed` | 必需 Artifact/事实/来源硬门/安全编译失败 | 无 | 不记录 |
| `cancelled` | 用户取消 | 无 | 不记录 |

V6.1 关键约束：`degraded` 可自动输出三端产物，但必须显示阶段降级摘要；不得使用误导性的「Qwen 智能整理」标签掩盖本地回退。

## 6. 缓存与恢复

### 6.1 缓存架构

与 V5.1 结构一致，V6.1 新增 Artifact：
- `knowledge/evidence-corrections.json`（证据纠错覆盖层）
- `knowledge/editorial-policy.json`（编辑策略）
- `knowledge/document-blueprint-v2.json`（文档蓝图）
- `knowledge/chapters/v3.1/*.json`（章节组件）
- `knowledge/document-v3.json`（Document v3.1）
- `knowledge/quality-report-v2.json`（质量报告）
- `state/previews/<revision>/page-report.json`（页面审计）

### 6.2 四级版本系统（V6.0）

| 版本 | 触发变化 | 失效行为 |
|------|---------|---------|
| `graph_version` | Graph 拓扑/State/Reducer/节点语义顺序 | 新建 thread，验证复用 Artifact |
| `implementation_version` | 节点代码 Bug/算法变化 | 当前节点及必要下游重算 |
| `contract_version` | Artifact Schema/语义 | Adapter/迁移或重算 |
| `policy_version` | Prompt/模型角色/决策规则 | 仅失效相关模型/决策节点 |

V6.1 新增：`tool_contract_version`、`editorial_policy_version`、`blueprint_contract_version`、`document_contract_version=document-v3.1`、`renderer_capability_version`、`prompt_version`、`quality_policy_version`。

### 6.3 Checkpoint 与缓存分工

- **Graph Checkpoint**：同一次 Job 的执行恢复（暂停/崩溃后继续）。
- **WorkspaceCache**：跨 Job、跨 Graph Thread 的计算复用。
- 新 `graph_version` 不迁移旧 Checkpoint；可复用通过校验的 Artifact。
- 取消的 thread 不恢复；用户再次启动创建新 Job 并复用 Artifact。

### 6.4 缓存恢复修复（V5.1）

`cached_result` 在 manifest 路径缺失时扫描 `output/<video_id>/` 目录补全 `.md/.docx/.pdf`。

### 6.5 URL 源缓存命中（V5.0）

`WorkspaceCatalog.find_by_url(url)` 下载前缓存命中。

### 6.6 旧 Workspace 认领

`LegacyArtifactAdapter` 单向只读认领；Document v2 只读；历史文件不主动删除。V6.1 默认复用 source/audio/transcript/frame/visual/CourseIR，从 `evidence.reconcile` 起重新执行。

## 7. 云端预算与 Function Calling

### 7.1 预算账本

`CloudRequestBudget`（V6.0）：单视频 `max_calls_per_video`（默认 5），全流程共享。`StageBudget`（V6.1）：分阶段限制总调用/Token/工具轮次/单工具返回字符/批次数/修订保留额度。预算比例：规划/观察 20%、正文 65%、修订保留 15%。

### 7.2 Function Calling 工具集

| 阶段 | 工具 | 模式 | 说明 |
|------|------|------|------|
| 规划 | `lookup_evidence` | 只读 | 返回有界来源段（top_k ≤ 5） |
| 规划 | `lookup_visual_facts` | 只读 | 返回视觉事实（top_k ≤ 4，不含图片数据） |
| 规划 | `get_renderer_capabilities` | 只读 | 返回 v3.1 渲染能力和 fallback |
| 规划 | `submit_blueprint` | 候选 State | 后续确定性校验才提交 Artifact |
| 写作 | `submit_chapter` | 强制结构化 | 分批写作，章指纹缓存 |
| 修订 | `get_page_detail` | 只读已有报告 | 不重新渲染，不返回截图 |
| 修订 | `submit_patch` | 候选 State | 白名单操作：add/remove/replace/move/set_layout_hint |
| 修订 | `finish_editing` | 请求最终审计 | 审计失败仍可拒绝完成 |

工具错误码：`TOOL_UNKNOWN`/`TOOL_ARGS_INVALID`/`TOOL_SCOPE_VIOLATION`/`TOOL_RESULT_TOO_LARGE`/`TOOL_MULTIPLE_MUTATIONS`/`TOOL_REVISION_CONFLICT`/`TOOL_BUDGET_EXCEEDED`/`TOOL_PROVIDER_UNSUPPORTED`/`TOOL_NO_PROGRESS`。

### 7.3 默认调用预算

| 场景 | 调用次数 | 阶段 |
|------|---------|------|
| 正常短视频（目标） | 2 | Blueprint + Writer |
| 一般问题 | 3 | + 观察/纠错 |
| 严重 ASR + 修订 | ≤ 4 | + 修订 |
| 长视频 | 1 + N 批 + 可选 1 修订 | 按批次数 |

### 7.4 紧凑载荷

与 V5.1 一致的 CourseIR 投影安全校验。V6.1 分层载荷：Blueprint 只发政策/摘要/索引/代表证据；Writer 只发 Blueprint 切片/当前批次/相关证据；Patch 只发失败组件/issue/邻居摘要。禁止每轮发送完整 transcript/CourseIR/Document。

### 7.5 多视频聚合

AggregateGraph：本地聚合始终可用，云端聚合为增强；独立 Job/Artifact/Checkpoint；逐批落盘和复用；云端聚合失败降级本地聚合。

## 8. 可溯源性保障

### 8.1 溯源链路

```
文档中的知识点
    ↓ Document v3.1 组件树 component_id → source_refs
KnowledgeUnit
    ↓ evidence_refs[].segment_ids + frame_ids
CourseIR claims + visual evidence
    ↓ source_ids → source_blocks
transcript.normalized segments（含 start/end 时间戳）
    ↓ timestamp_url(video_id, start)
video-study://play/<video_id>?t=<seconds>
    ↓ Windows 协议注册 → 本地播放器
ffplay -ss <seconds> 定位播放
```

V6.1 Document v3.1 中每个非装饰组件包含 `component_id`、`semantic_role`、`source_refs`、`origin`、`confidence`，溯源精度到组件级。公式和图片必须精确追溯；无法确认的公式标记不确定，不得补造。

### 8.2 Provenance 追踪（V6.1）

每个文档记录阶段来源：

```yaml
provenance:
  intent: cloud_tool | cloud_structured | local_deterministic
  evidence_reconcile: cloud_structured | local_vlm | local_rules | skipped
  blueprint: cloud_tool | cloud_structured | local_deterministic
  chapter_writing:
    chapter_001: cloud_structured | local_deterministic
  page_audit: local_vlm | local_rules
  final_repair: cloud_tool | local_deterministic | none
```

### 8.3 不可违反的边界

| 边界 | 保障机制 |
|------|---------|
| 视频不上传 | 云端只发送紧凑 CourseIR 投影，不含视频/截图/base64 |
