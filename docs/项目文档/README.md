# 知影项目文档

这里放的是给人阅读的项目说明。当前运行状态、执行边界和机器合同仍以 [`项目索引`](../项目索引.md)、[`AI 执行入口`](../AI执行入口.md) 与 `docs/architecture/*.yaml` 为准。

## 按你的目的选择文档

| 我想了解什么 | 建议阅读 | 预计用时 |
|---|---|---:|
| 软件能做什么、怎样操作 | [软件介绍](软件介绍.md) | 8 分钟 |
| 产品解决什么问题、边界是什么 | [业务文档](业务文档.md) | 10 分钟 |
| 怎样定位代码、排查问题、提交修改 | [开发文档](开发文档.md) | 15 分钟 |
| 系统为什么这样设计、数据怎样流动 | [架构详解](架构详解.md) | 20 分钟 |

第一次接触项目，推荐按以下顺序阅读：

1. [软件介绍](软件介绍.md)：先形成对产品的直观认识；
2. [业务文档](业务文档.md)：理解用户、价值和产品边界；
3. [开发文档](开发文档.md)：开始定位代码和运行测试；
4. [架构详解](架构详解.md)：处理跨模块问题时再深入阅读。

- [质量与降级图](quality_degradation.svg)：哪些检查决定成功、降级或失败。

## 阅读约定

- 文档中的“当前”对应 **V6.1 / 产品版本 1.0.0**。
- “统一内容结构”是正文、公式、图片、来源与三种输出之间的桥梁；它是内部实现，不要求读者记住格式名称。
- `Artifact` 可理解为某一步生成并保存的中间结果。
- `Port` 可理解为业务代码调用外部能力的统一接口。
- `Graph` 可理解为可恢复、可检查的处理流程图。
- 版本升级过程和历史执行证据不放在这里，见 [`迭代升级`](../迭代升级/)；故障定位见 [`problem-index.yaml`](../diagnostics/problem-index.yaml)。

## 内容维护原则

这组文档只解释“读者需要知道的内容”，不复制机器合同，也不记录每次迭代的实施流水账。发生冲突时，优先级如下：

1. 代码、测试和实际执行结果；
2. `docs/architecture/*.yaml` 与 `docs/diagnostics/problem-index.yaml`；
3. `docs/项目索引.md` 与 `docs/AI执行入口.md`；
4. 本目录中的说明性文档。
