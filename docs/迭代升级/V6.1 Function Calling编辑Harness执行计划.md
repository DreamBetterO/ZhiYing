# V6.1 Function Calling 编辑 Harness 执行计划

> 唯一实施顺序：`CP61-0 → CP61-8`。  
> 当前状态：CP61-0～CP61-8 已完成；V6.1 / `1.0.0` 已于 2026-09-03 经用户确认。
> 主方案：[V6.1 Function Calling 编辑 Harness 升级方案](V6.1%20Function%20Calling编辑Harness升级方案.md)。  
> 机器合同：[V6.1 Function Calling 编辑 Harness 目标合同](V6.1%20Function%20Calling编辑Harness目标合同.yaml)。

## 0. 执行规则

- 本计划是 V6.1 唯一阶段/恢复点来源。`当前架构升级状态.yaml` 只记录正在执行的 CP，不复制本计划。
- 每个 CP：先新增失败测试/黄金期望 → 最小实现 → 责任测试 → 原始结果记录 → 检查点提交资格。
- 未通过当前 Gate 不得修改下一 CP 的生产路径。
- 当前 dirty worktree 属于用户和 V6.0 实现；实施前记录文件基线，不重置、不覆盖无关修改。
- 底层 source/audio/transcript/frame/visual/CourseIR 默认复用；禁止为文档层开发反复重跑长视频。
- 同一 Workspace 的写任务串行；Tool Call 不得并发修改同一 document revision。
- CP61-0～CP61-6 使用 mock/replay provider，不发真实云请求。
- 真实云、模型变更、依赖变更、长视频、便携构建分别授权。
- 每个 CP 的 rollback 是代码/active contract 回退，不删除已生成 Workspace/Artifact。

## CP61-1｜建立编辑协议与完整本地语义链

### 目标

先证明云端完全不可用时也不恢复旧模板，再引入 Function Calling。

### 任务

1. 建立 `EditorialPolicy v1`：
   - required/preferred/forbidden；
   - 内容/结构/视觉/公式偏好；
   - 硬合同冲突和逐条 compliance predicate。
2. 建立 `LocalIntentCompiler`，覆盖批准的最小自然语言集合。
3. 建立不可变 transcript 上的 `EvidenceCorrectionOverlay v1`：
   - 本地异常候选；
   - accepted/rejected/unresolved；
   - source/confidence/method。
4. 建立 `DocumentBlueprint v2` Schema/validator：
   - 不含 `source_section`；
   - 只引用已存在 ID；
   - 组件/布局/回退受 CapabilityManifest 限制；
   - required/forbidden 可验证。
5. 建立 `LocalBlueprintPolicy`：concept/procedure/case/comparison/mixed。
6. 建立 `LocalDocumentComposer` 和确定性最小 repair：
   - 不把原始口语直接贴成规则/步骤；
   - formula/image/source component 保持语义；
   - 质量不足进入 unresolved/degraded。
7. 新增 Artifact ID、validator、fingerprint 和 cache contract。

## CP61-2｜Document v3.1 原生三端渲染与质量审计

### 目标

先打通真实组件能力，避免 LLM 得到虚假的 renderer capability。

### 任务

1. 升级 Document 合同：`schema_version=3`、`contract_version=document-v3.1`。
2. 将组件树作为唯一新写权威：heading/paragraph/list/equation/table/image/container/callout/page_break/source_reference。
3. 实现 Markdown 原生 v3.1 renderer。
4. 实现 Word 原生 v3.1 renderer：
   - 语义 Heading/List/Table/Image；
   - LaTeX/数学 AST → OMML；
   - caption/alt text/source hyperlink；
   - style/layout token，不接受任意 XML/坐标。
5. 实现 PDF 与同一组件树语义一致；明确 Word 转 PDF 与 built-in fallback 能力差异。
6. 删除新文档生产的 `v3_to_v2` 路由；只保留历史只读 adapter。
7. 建立 `QualityReport v2` 和 `PageAuditReport v1`：
   - 意图、来源、ASR、公式、视觉、重复；
   - 分页、孤行、异常留白、溢出；
   - 三端组件覆盖和 OOXML 统计。
8. Preview 为 revision-scoped 派生 Artifact；缓存命中不重复渲染。

### 主要文件

- `src/zhiying/documents/v3.py`（Canonical Document v3 合同）

- `src/zhiying/editorial/quality.py`

### 责任测试

- 组件到 Markdown/Word/PDF 映射参数化测试；
- Word OOXML：Heading、numbering、table width、drawing、hyperlink、OMML；
- PDF 页渲染黄金；
- forbidden 不被 renderer 注入；
- 历史 v2/v3 只读打开；
- 三端组件 parity。

### Gate
