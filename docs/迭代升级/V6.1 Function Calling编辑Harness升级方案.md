## 1. 问题结论与责任定位

V6.0 已完成编排迁移，但文档质量升级没有真正落地。V6.1 不以“增加模型次数”为目标，而是修复以下责任错位。

### 1.1 LLM 名义参与、实际无编辑权

当前 `document.plan` 虽标记支持云端，但生产实现只是把旧式 Document section 包装为 DocumentPlan：

- 章节来自旧 section 的机械复制；
- 布局统一为 `full_width`；
- `source_section` 原样进入计划；
- `chapter.compose` 机械转换组件；
- `chapter.validate` 主要校验标题/ID；
- `chapter.repair` 只修空标题。

因此用户自然语言只能影响上游标题和正文，不能删除旧栏目、改变布局或重构文档树。

### 1.2 Document v3 未被原生渲染

当前 Markdown/Word/PDF 生产渲染会把 Document v3 转回 v2 视图，旧渲染器继续硬编码：

- 内容导览、学习目标、固定章节编号；
- 课程复习、知识主线、关键规则、待回看问题；
- 看图重点、图片解释固定话术；
- 普通文本公式而非 Word 原生 OMML。

V6.1 必须删除生产 `v3_to_v2` 渲染路径。兼容读取适配器只允许用于历史诊断，不得参与新产物。

### 1.3 云端失败被静默包装成成功

真实样本 `高数-定积分定义-be06877a42cf` 的 `knowledge.units` 因响应字段类型错误退回本地，最终仍显示 `cloud_summary / Qwen 智能整理`。本地原始转写中的“圆寒数、长数、级分、阶段”等错误进入正文，自检警告仍通过。

V6.1 必须按阶段记录真实来源和降级状态；规划使用云端不能把本地正文伪装为云端正文。

### 1.4 当前验证只证明“文件存在”

现有 Document/Render 验证偏结构合法和文件非空，不能识别：

- 用户禁止栏目仍出现；
- 大段口语和 ASR 错词；
- 数学公式为普通文本；
- 图片重复、无教学作用或说明机械；
- 页面列表断裂、孤行和异常留白；
- Markdown/Word/PDF 语义不一致；
- 云端阶段已降级却显示成功。

V6.1 必须建立内容、意图、来源、公式、视觉、页面和跨格式质量门。

## 2. 升级目标

V6.1 的唯一核心目标是：

> 在 V6.0 全链路 LangGraph 基线上，引入受控 Function Calling 编辑 Harness，让 LLM 在证据和渲染能力范围内真正拥有文档设计、主动观察和局部修订权，同时保留经济、可恢复、可测试的本地确定性完成路径。

验收结果必须同时满足：

1. 用户可以用自然语言表达大致偏好，系统将其编译为可审计的 `required / preferred / forbidden` 约束。
2. LLM 生成真正的 `DocumentBlueprint`，而不是旧 section 包装。
3. LLM 可以按需查询来源、视觉事实和页面审计，但不能访问任意文件、Shell、网络或秘密。
4. LLM 只能提交候选 Blueprint/局部 Patch；确定性节点负责校验、应用和 Artifact 提交。
5. 编辑阶段默认 Blueprint + Writer；知识整理按 unit 有界分批，所有云调用共享每视频预算；纠错、观察和修订由问题触发。
6. Function Calling 不稳定时先降级到结构化云端，云端不可用时再走完整本地确定性链。
7. Document v3.1 组件树被 Markdown、Word、PDF 原生消费；Word 数学公式使用 OMML。
8. 页面预览由本地规则和通过门禁的 Qwen3-VL 检查；页面图片不上传云端。
9. 任何局部降级均进入 provenance 和终态；不得用“智能整理”掩盖本地回退。
10. 两个真实高数样本和强/弱视觉黄金 fixture 证明质量提升且无链路回归。

## 3. 明确非目标

V6.1 不包含：

- 自由自治 Agent 或无界 ReAct 循环；
- 让 LLM 接管 Source、ASR/VLM 资源、缓存、授权、Checkpoint 或发布；
- 任意 `write_file`、`run_shell`、任意路径读取、删除和外网工具；
- MCP Server、通用 Tool Marketplace 或多 Agent 协作；
- 云端图片、视频帧、页面截图上传；
- 强制安装完整 LangChain、`langchain-openai` 或新本地文本模型；
- 让 Qwen3-VL-2B 承担全文写作或全局规划；
- 任意 DOCX XML/坐标生成；
- 同时重构现有 GraphRuntime、NodeExecutor 和 ArtifactStore 核心事务；
- 覆盖或删除历史 Document v2/v3、Workspace、Output 或旧 Checkpoint。

## 4. 总体架构

V6.1 保持 LangGraph 为唯一生产编排器，在 `knowledge.units` 与 `document.compile` 之间替换现有伪规划/机械章节链：

```text
knowledge.units + visual.evidence + transcript.normalized + editorial brief
  → evidence.reconcile
  → intent.compile
  → EditorialAgentSubgraph
      ├─ blueprint.agent
      ├─ blueprint.validate / commit
      ├─ chapter.write[N]
      ├─ document.assemble
      ├─ preview.render
      ├─ quality.audit
      ├─ revision.agent（failed-only）
      └─ patch.validate / apply（最多一次默认修订）
  → document.compile
  → document.validate
  → render.markdown.native_v3
  → render.word.native_v3
  → render.pdf.native_v3
  → render.verify.quality
```

保留不变：

- JobGraph、SourceGraph、VideoGraph、AggregateGraph 的唯一编排地位；
- NodeExecutor 的缓存、staging、校验、原子提交和事件语义；
- ArtifactStore/WorkspaceCache 与 Graph Checkpoint 分工；
- 单视频一个活动 VLM、GPU 全局串行；
- JSON → Markdown → Word → PDF 与 `video-study://` 来源回链；
- Application/Desktop 与 ports/adapters 边界。

## 5. 宏观确定性、微观 Agent 化

### 5.1 LangGraph 决定

- 节点和子图拓扑；
- 是否进入证据纠错；
- 是否允许云端和 Function Calling；
- 阶段预算、轮次和超时；
- Tool Call 路由、校验错误反馈、重试和熔断；
- Preview、Audit、Patch、Finalize 的顺序；
- 降级、终态、Artifact 提交与发布。

### 5.2 LLM 决定

- 是否需要查看更多证据；
- 本课应采用的文档类型、章节和知识组织；
- 可选栏目增删、重命名、排序和详略；
- 公式、表格、图片、提示框和分页等表达选择；
- 对质量报告中失败组件的局部 Patch；
- 何时完成当前编辑阶段。

### 5.3 LLM 永远不能决定

- 云授权、图片授权、API 端点和密钥；
- 任意路径和文件写入；
- Artifact/Checkpoint/缓存版本；
- GPU、ASR、VLM 和进程资源调度；
- 是否删除历史数据；
- 跳过事实/来源/公式/质量硬门；
- 把 failed/degraded 改成 succeeded；
- 直接发布最终产物。

## 6. EditorialAgentSubgraph

### 6.1 子图状态

`EditorialState` 只保存小型、可序列化数据：

- `schema_version`、`graph_version`、`video_id`、`phase`；
- `editorial_policy_ref`、`evidence_overlay_ref`、`course_ir_ref`；
- `blueprint_candidate_ref`、`accepted_blueprint_ref`；
- `document_revision`、`document_candidate_ref`；
- `preview_report_ref`、`quality_report_ref`；
- `messages`（当前阶段有界消息）；
- `tool_turns`、`tool_failures`、`no_progress_count`；
- 阶段调用/Token 使用和剩余预算；
- provenance、问题摘要和终态。

禁止进入 State/Checkpoint：完整 transcript、CourseIR、Document、页面图片、模型实例、端口、凭据、任意异常响应正文。大对象先写 Artifact，State 只存安全引用。

### 6.2 子图持久化

- EditorialAgentSubgraph 作为显式子图挂入 VideoGraph；不得藏在普通 Python 循环或 NodeExecutor 内部。
- 使用 per-invocation 子图状态并继承父 Graph Checkpointer。
- 消息历史只保留当前阶段需要的 System/Tool/Assistant turn；章节写作默认无跨章对话记忆。
- 每个提交的 Blueprint、Chapter、Patch、Audit 均为可缓存 Artifact。
- 新 `graph_version` 不迁移 V6.0 Checkpoint；可复用通过合同验证的上游 Artifact。

## 7. Function Calling 标准实现

### 7.1 新端口

保留 `CloudJsonPort`，新增可选 `CloudToolPort`：

```text
invoke_turn(
  messages,
  tools,
  tool_choice,
  stage,
  budget,
  cancel_check
) -> ToolTurn
```

`ToolTurn` 只包含：

- `content`；
- `tool_calls`；
- `invalid_tool_calls`；
- `model`、`attempts`、`usage`；
- `finish_reason`；
- 安全错误码，不包含请求头、密钥或完整供应商响应。

实现约束：

- 复用当前 OpenAI Python SDK 与兼容端点；不因基本 Function Calling 强制安装完整 LangChain。
- 将供应商 `tool_calls` 规范化为 `AIMessage.tool_calls`，工具结果使用 `ToolMessage`。
- 使用 LangGraph `ToolNode` 执行只读工具；使用条件路由区分观察、提交和结束动作。
- `Command` 只允许更新小型 State 和受控路由，不直接写业务 Artifact。
- 同一调用只允许一个修改型工具；多修改调用返回 `TOOL_MULTIPLE_MUTATIONS` 并要求重试。
- 工具描述按阶段最小绑定；不得每轮发送全部工具 schema。

### 7.2 工具集

#### 规划阶段

`lookup_evidence`

- 输入：`unit_ids`、`query`、`top_k <= 5`、`include_neighbors`；
- 输出：有界 `source_id / segment_ids / timestamp / text / confidence / correction_status`；
- 只读，不返回完整 transcript 或本地绝对路径。

`lookup_visual_facts`

- 输入：`unit_ids`、`purpose = explain|evidence|compare|recap|formula`、`top_k <= 4`；
- 输出：本地核实的对象、文字、公式候选、关系、时间戳、置信度、裁剪建议 ID；
- 不返回图片数据，不触发云图片上传。

`get_renderer_capabilities`

- 输入：需要确认的组件/布局类型；
- 输出：Document v3.1 支持、限制和确定性 fallback；
- 只读、版本化、可缓存。

`submit_blueprint`

- 输入：完整 `DocumentBlueprintCandidate`；
- 输出：只写候选 State；
- 后续必须进入 `blueprint.validate`，工具本身不提交 Artifact。

#### 修订阶段

`lookup_evidence`

- 与规划阶段相同，但默认只允许质量报告涉及的 unit/component。

`get_page_detail`

- 输入：已生成 `page_ids/component_ids`；
- 输出：PageAuditReport 中的密度、分页、重复、公式、图片和组件定位；
- 只读取已存在预览报告，不在工具内部重新渲染，也不返回截图。

`submit_patch`

- 输入：`base_revision`、`operations`、`issue_ids`、理由；
- 操作白名单：`add/remove/replace/move_component`、`set_layout_hint`、`set_style_token`；
- 不允许路径、脚本、XML、任意 JSON Pointer 或整篇替换；
- 只写 Patch 候选 State，后续由 `patch.validate/apply` 执行。

`finish_editing`

- 输入：完成理由、已处理 issue ID、剩余限制；
- 只请求进入最终审计；审计失败仍可拒绝完成。

### 7.3 工具错误

工具错误必须转成稳定、安全、可重试的 ToolMessage：

- `TOOL_UNKNOWN`；
- `TOOL_ARGS_INVALID`；
- `TOOL_SCOPE_VIOLATION`；
- `TOOL_RESULT_TOO_LARGE`；
- `TOOL_MULTIPLE_MUTATIONS`；
- `TOOL_REVISION_CONFLICT`；
- `TOOL_BUDGET_EXCEEDED`；
- `TOOL_PROVIDER_UNSUPPORTED`；
- `TOOL_NO_PROGRESS`。

同一错误最多反馈一次修正机会；第二次仍失败则按能力级别降级，不得无界让模型重试。

## 8. LLM 参与与 Token 合同

### 8.1 默认调用

| 阶段 | 默认 | 典型调用 |
|---|---:|---:|
| evidence.reconcile | 否；异常触发 | 0 或 1 |
| blueprint.agent | 是 | 1；主动观察时 2 |
| chapter.write | 是 | 每批 1 |
| cloud critic | 否；本地门失败触发 | 0 或 1 |
| patch | 与 critic 合并提交 | 不额外全文重写 |
| page/final audit | 本地 | 0 |

正常短视频的编辑阶段目标仍为 Blueprint + Writer；知识整理阶段按知识单元有界分批，默认每批 1 个 unit，以避免端点遗漏计划或交叉引用。全部调用共享每视频总预算，当前默认最多 12 次；长视频按正文批次数增加，但不开放额外无界工具轮次。质量优先于用不稳定的大批量请求压缩调用次数。

### 8.2 载荷分层

- Blueprint：用户政策、课程级摘要、unit 索引、重要度、代表证据、渲染能力摘要。
- Writer：接受后的 Blueprint、当前批次 unit、相关来源和视觉事实。
- Patch：失败组件、issue、相邻组件摘要和相关证据。
- 禁止每轮重复发送完整 transcript、CourseIR、Document 或全部图片描述。

### 8.3 阶段预算

新增 `StageBudget`，同时限制：

- 总调用数；
- 总输入/输出 Token；
- 每阶段调用/Token；
- 工具轮次；
- 单工具返回字符；
- 单批 unit/目标输出长度；
- 修订保留额度。

默认预算比例：规划/观察约 20%，正文约 65%，修订保留约 15%。正文不得消耗修订保留；预算不足时优先压缩 `mention/brief` 内容，而不是取消核心章节或最终修订。

规模按 CourseIR 有效字符、unit 数量、深度分布和预计输出计算，不按视频时长硬编码。

知识整理的 API 硬输出上限独立配置：`organizer_request_max_output_tokens=0` 表示不发送 `max_tokens`，由端点自然完成；正整数表示显式硬上限。无论是否发送硬上限，本地输入预算、unit 分批、每视频调用上限和超时仍然生效。

### 8.4 缓存与费用

每个云结果指纹包含：

- 角色/阶段、模型、provider capability；
- Prompt/Tool schema/Policy/Contract 版本；
- 输入 Artifact digest、blueprint/document revision；
- 用户意图 hash、内容档位、视觉档位；
- 关键生成参数。

Checkpoint 重放和工具重试必须先查询缓存；同一工具名+规范化参数+revision 的只读结果可复用。不得因恢复再次支付已成功的云调用。

云端授权运行不得复用 `status=degraded` 的历史结果；`cloud`、`tool_native`、`structured_only` 只有在步骤终态非 degraded 且 Artifact/指纹有效时才能满足新的 cloud 请求。

## 9. 模型能力门禁与三级执行

### 9.1 `tool_native`

- 模型稳定返回标准 `tool_calls`；
- 参数通过 schema；
- tool_call_id 往返正确；
- 黄金用例工具选择、退出和成本通过；
- 启用完整 EditorialAgentSubgraph。

### 9.2 `structured_only`

触发：模型/端点不支持工具、连续非法 tool call、Function Calling 能力探针失败。

- 使用 `CloudJsonPort` 或强制输出工具生成 Blueprint/Chapter/Patch；
- Graph 预先构造充分 EvidencePack；
- 不开放主动观察循环；
- 云端正文仍可用，记录 `editor_mode=structured_cloud`；
- 若质量门通过可为 `succeeded`，但 provenance 必须如实记录工具能力降级。

### 9.3 `local_deterministic`

触发：未授权、熔断、所有模型失败、预算耗尽或用户选择本地。

- 不构造 CloudToolPort/CloudJsonPort；
- 运行完整本地编辑链并输出三端产物；
- 任务通常标记 `degraded`，除非用户明确选择本地模式且本地质量门全部通过；
- 不恢复 V6.0 固定旧模板。

能力按模型和端点记录，不因 OpenAI 兼容接口而默认 `tool_native`。真实能力探针属于云推理，必须包含在已授权的作业预算内或另获测试授权。

## 10. 证据纠错覆盖层

### 10.1 原则

- 原始 transcript 不可变；
- 纠错写入 `knowledge/evidence-corrections.json`；
- 每条修正记录 raw、candidate、accepted、source span、证据、置信度和方法；
- 下游读取 `EffectiveEvidenceView = raw + accepted overlay`；
- 低置信度不自动改写，进入 unresolved。

### 10.2 触发

本地先检测：

- 领域高频近音/同音错误；
- 同一术语多种写法；
- 公式上下文异常汉字；
- 标题/幻灯片文字与 ASR 冲突；
- 口头填充词密度和句法异常；
- 自检中关键术语、条件、否定和方向词风险。

只把疑点窗口发送给云端，不发送完整 transcript。Qwen3-VL 只验证局部幻灯片/公式/页面证据，不承担全文纠错。

## 11. EditorialPolicy 与 DocumentBlueprint

### 11.1 EditorialPolicy

用户自然语言先由 `intent.compile` 形成：

- `required`：必须出现/遵守；
- `preferred`：尽量满足；
- `forbidden`：不得出现；
- `content_focus`、`structure_preference`、`visual_preference`、`formula_preference`；
- `hard_contract_conflicts`；
- 每条约束的原文 span、解释和可验证谓词。

云端可增强意图理解；本地 `LocalIntentCompiler` 至少可靠支持：

- 禁止/需要内容导览、学习目标、课程复习、固定编号；
- 例题+思路、概念+性质、步骤、对比等结构关键词；
- 精简/推荐/丰富；
- 图片少/多/禁止；
- 公式优先、表格优先、来源显示偏好。

复杂意图本地不能完全解析时记录 `partially_satisfied`，不得伪装完全遵循。

### 11.2 DocumentBlueprint v2

Blueprint 不含旧 `source_section`，至少包含：

- `blueprint_id`、`schema_version=2`、policy/evidence/capability version；
- 文档类型、受众、用途、密度和设计 token；
- 可选 front matter/导航策略；
- 章节及稳定 component ID；
- 每章目标、unit/source 引用、深度和预计长度；
- 组件树意图：paragraph/list/equation/table/image/callout/container/page_break/source_reference；
- 图片职责、公式证据策略、布局提示；
- required/forbidden 约束映射；
- 每组件 fallback；
- 未解决问题和降级允许范围。

Blueprint 只能引用输入存在的 unit/source/visual ID。不得包含 Word XML、文件路径、任意坐标或 Markdown 正文。

## 12. Document v3.1 与原生渲染

### 12.1 Document v3.1

- 保持 `schema_version=3`，升级 `contract_version=document-v3.1`；
- component tree 是唯一新写权威；
- 每个非装饰组件包含稳定 ID、semantic role、source refs、origin、confidence；
- equation 保存规范 LaTeX/数学 AST 和证据；
- image 保存 Artifact/visual ID、职责、caption、alt text、crop ID 和来源；
- style/layout 仅使用 capability manifest 中有限 token；
- 不保存 renderer 私有 XML。

### 12.2 三端原生 Renderer

- Markdown：直接遍历 v3.1 组件树；
- Word：直接遍历 v3.1，语义 Heading/List/Table/Image，公式生成 OMML；
- PDF：优先由 Word 转换或直接消费同一组件树，保持语义等价；
- 不允许生产 `v3_to_v2`；
- 历史 v2/v3 仅通过只读迁移/诊断适配器展示。

Renderer 不得自动注入旧业务模板。只允许自动加入用户/合同明确的来源、页码、文档元数据和无障碍字段。

### 12.3 Preview 与 PageAudit

每次接受初稿或 Patch 后按需生成 revision-scoped 预览：

- 页面/组件边界；
- 标题层级、列表、表格、图片、公式计数；
- 孤行、跨页列表、异常留白、溢出和重复；
- 图片尺寸、裁剪、caption 与邻近解释；
- 公式是否原生、是否降级；
- 跨格式组件覆盖。

确定性检查先运行；通过任务级门禁的本地 Qwen3-VL 可检查页面截图并只写结构化报告。页面截图不得进入云端 ToolMessage。

## 13. 本地确定性完成链

V6.1 的本地链不是旧模板 fallback，而是完整语义编译器：

```text
LocalIntentCompiler
→ LocalEvidenceReconcile
→ LocalBlueprintPolicy
→ LocalDocumentComposer
→ LocalDocumentAudit
→ LocalDeterministicRepair
→ native v3.1 renderers
```

`LocalBlueprintPolicy` 只维护少量通用结构策略：

- `concept`：定义 → 性质/关系 → 条件/边界；
- `procedure`：目标 → 输入 → 步骤 → 结果/失败处理；
- `case`：题目 → 识别 → 思路 → 推导 → 结论/变式；
- `comparison`：对象 → 维度 → 差异 → 选择条件；
- `mixed`：按知识依赖形成章节，不平均分配。

这些是语义组织策略，不是固定可见栏目。导览、目标、复习、开放问题始终由 policy 决定是否存在。

本地无法可靠精炼时：

- 不把大段原始口语伪装成“规则/步骤”；
- 生成简洁、可追踪的降级资料；
- 保留 unresolved 和待核对来源；
- 公式证据不足时使用带来源截图/文本降级并显式标记；
- VLM 不可用时不插入低置信度图片；
- 不伪造外部知识或精确等式。

## 14. 质量门

### 14.1 意图

- required 全部满足；
- forbidden 命中数为 0；
- preferred 给出满足/未满足原因；
- 硬合同冲突不可由模型覆盖。

### 14.2 内容与来源

- 所有事实组件可追到 source/unit/visual；
- 无来源模型补充不得进入正文事实；
- ASR 异常、口头填充和直接复制密度低于黄金阈值；
- 关键条件、否定、边界和步骤完整；
- 标题/正文/列表无近重复。

### 14.3 数学

- 数学课程中可确认公式进入 equation 组件；
- Word 原生 OMML 数量与 equation 组件一致，降级须有原因；
- 等价变换、常数因子、积分/微分顺序通过确定性或证据校验；
- 来源不足不补造结果。

### 14.4 视觉

- 图片只在 `supportive|required` 且证据满足时出现；
- 每图有职责、来源、caption/alt text；
- 同场景重复受阈值约束；
- no_match 正常，不用最近帧兜底；
- 图片与相邻组件的 unit/source 匹配。

### 14.5 页面与跨格式

- 无溢出、异常空白、孤立列表项和不可读图片；
- 标题、列表、表格、公式、图片在三端语义覆盖；
- Word 样式、超链接、OMML、媒体关系可机器检查；
- PDF 逐页渲染检查；
- Markdown 不泄露本地绝对路径或内部 ID。

## 15. 状态与 provenance

每个文档记录阶段来源：

```yaml
provenance:
  intent: cloud_tool | cloud_structured | local_deterministic
  evidence_reconcile: cloud_structured | local_vlm | local_rules | skipped
  blueprint: cloud_tool | cloud_structured | local_deterministic
  chapter_writing:
    chapter_001: cloud_structured | local_deterministic
  page_audit: local_vlm | local_rules
  final_repair: cloud_tool | local_deterministic | none
```

终态：

- `succeeded`：必需 Artifact 和全部硬质量门通过；
- `degraded`：产物完整可用，但模型/视觉/公式/意图等增强局部降级，UI 明确原因；
- `failed`：必需 Artifact、事实/来源硬门或安全编译失败；
- `cancelled`：用户取消。

自动发布策略已收敛：`degraded` 可以生成并展示三端产物，但不得使用误导性的“Qwen 智能整理”标签，必须展示阶段降级摘要。

## 20. 完成定义

同时满足以下条件才可声明 V6.1 完成：

- EditorialAgentSubgraph 是生产文档编辑唯一链路；无隐藏自由循环。
- Function Calling、结构化云端和纯本地三级路径全部通过。
- 无 Function Calling 模型时不会阻断云端结构化写作。

- 用户 forbidden 旧模板后，产物旧栏目为 0。

## 21. 已收敛决策

- Function Calling 是 V6.1 核心机制，但仅限编辑子图的主动观察和局部编辑。
- 宏观流程、权限、缓存、资源、提交、质量终态继续确定性控制。
- 编辑阶段默认 Blueprint + Writer；知识整理默认按 unit 分批；纠错、观察、修订按问题触发且共享总预算。
- 云端 Function Calling 不可用时先降级结构化云端，再降级本地。
- 本地 fallback 是完整语义编译链，不恢复旧可见模板。
- 页面图片仅本地检查；云端只接收结构化页面报告。
- degraded 产物允许自动输出，但必须显式标识且不得伪报智能整理成功。
- V6.1 已随正式产品 `1.0.0` 实施并通过验收；`1.0.0rc1/rc2` 仅保留为历史实施阶段标识。
