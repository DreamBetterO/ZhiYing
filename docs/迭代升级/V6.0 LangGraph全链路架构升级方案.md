> 状态：`approved_target`（2026-08-20，尚未实施）。  
> 当前可运行基线：产品 `0.5.1`，15 步 `StepRegistry → PipelineRunner → ArtifactStore/WorkspaceCache`。  
> 目标：架构 `V6.0`，产品由 `1.0.0-alpha` 经阶段验收后发布 `1.0.0`。  
> 执行入口：[V6.0 LangGraph 全链路升级执行计划](V6.0%20LangGraph全链路升级执行计划.md)。

## 0. Agent 使用规则

本文件是 V6.0 的**目标架构权威文档**，面向执行升级、审查实现和排查架构偏移的 Agent。执行前必须依次读取：

1. 根目录 `AGENTS.md` / `AGENTS.local.md`；
2. `docs/项目索引.md`；
3. `docs/AI执行入口.md`；
4. `docs/迭代升级/当前架构升级状态.yaml`；
5. 本文件；
6. V6.0 执行计划与目标合同；
7. 当前 `docs/architecture/*.yaml`、`docs/diagnostics/problem-index.yaml`、责任模块和测试。

执行纪律：

- 当前代码和 `docs/architecture/*.yaml` 在检查点切换前仍是运行事实；本文件描述获批目标，不得把“计划”伪报为“已实现”。
- 严格按执行计划 CP0→CP8 推进；一个检查点未验收，不得跨阶段修改后续业务协议。
- 编排等价迁移与质量升级必须分离。先让 LangGraph 等价接管，再改变知识、模型和文档质量。
- 每次修改先写失败回归测试；只改当前检查点的最小责任模块；不得顺手重构无关代码。
- 云请求、图片云上传、模型下载、依赖重装、长视频重跑和便携包重建仍需分别授权。
- 不读取、打印或提交 `.env`；Graph State、Checkpoint、事件和缓存不得包含密钥。
- 用户未重新批准前，不扩展 MCP、多 Agent、Web 服务、端口监听或通用插件平台。

## 1. 升级目标

V6.0 同时解决两类问题，但通过不同阶段实施：

1. **执行架构**：由 LangGraph 接管源获取、单视频、多视频、聚合与发布全链路，成为唯一编排器；保留并复用已经验证的 Artifact、缓存、原子提交、取消、诊断和端口边界。
2. **产物质量**：让本地确定性链路始终可运行，现有本地模型按能力参加局部语义判断，云端按阶段可选增强；由 LLM 生成受约束的 `DocumentPlan`，由本地编译器稳定产出 Document v3、Markdown、Word 和 PDF。

成功不是“装上 LangGraph”，而是同时达到：

- 全部业务数据处理均经 GraphRuntime；生产代码中不存在第二套执行调度器；
- 云端完全不可用时仍能生成完整产物，质量降低必须显式标记；
- 节点、动态任务、模型调用、降级、成本和 Artifact 均可追溯；
- Bug 修复只失效责任节点及必要下游；
- 旧 Workspace 不破坏，昂贵且可信的底层 Artifact 可验证后复用；
- 高数、强视觉、弱视觉三类黄金样本证明结构、公式和图文质量提升。

## 2. 明确非目标

V6.0 首版不包含：

- MCP Server 的实际实现；仅允许保留窄扩展接口；
- 多 Agent 或自由自治 Agent 循环；
- Web UI、本机 HTTP 服务、端口监听或 `serve` 命令；
- 任意 Word XML、任意坐标排版或自演化渲染插件；
- 人工时间旅行/Checkpoint 编辑 UI；
- 默认上传图片或视频帧到云端；
- 强制下载新的本地文本模型；
- 多视频 GPU 并行；
- 原地覆盖 Document v2 或主动清理历史 Workspace；
- 在等价接管阶段顺手修改知识算法或文档样式。

## 3. 最终系统边界

LangGraph 接管所有产生、转换或聚合业务数据的流程：

```text
JobGraph
├─ SourceGraph
│  ├─ local.resolve
│  └─ url.preflight → url.acquire → source.verify
├─ VideoGraph × N（首版按队列顺序）
│  ├─ media.probe → audio.extract
│  ├─ transcript.decode → transcript.normalize → transcript.enrich
│  ├─ frames.candidates → visual.plan → visual.evidence
│  ├─ knowledge.course_ir → document.plan
│  ├─ chapter.compose → chapter.validate → chapter.repair（至多一次）
│  ├─ document.compile → document.validate
│  └─ render.markdown → render.word → render.pdf → render.verify
├─ AggregateGraph（aggregate_mode != none 时）
└─ job.finalize
```

不进入 Graph 的职责：

- Desktop View 的控件、窗口和设置编辑；
- Application DTO 构造、用户授权确认和结果展示；
- `video-study://` 本地播放器；
- 只读诊断、历史浏览和缓存清理等维护操作。

边界要求：

- UI 不得判断业务缓存并绕开 Graph。当前 Controller 的 `cached_result` 跳过逻辑在切换期后删除；所有任务都提交 Graph，由节点缓存决定是否执行。
- URL 单独下载也必须通过 SourceGraph；不得保留绕开 Graph 的生产下载编排。
- 本地/云端聚合都必须通过 AggregateGraph；多视频不自动聚合，由 `aggregate_mode = none | local | cloud` 显式决定。
- `pipeline.py` 可保留为兼容门面，但只翻译请求并调用 GraphRuntime，不含业务编排。

## 4. 唯一编排器与保留内核

### 4.1 LangGraph 负责

- Graph/子图拓扑；
- 节点调度、条件路由和动态任务；
- 同版本运行的暂停、Checkpoint、恢复和取消终态；
- 局部重试、降级路线和 fan-out/fan-in；
- Job/Video/Task 执行状态与路径。

### 4.2 LangGraph 不负责

- 大文件和业务 JSON 的长期存储；
- 跨 Job 的计算结果缓存；
- ffmpeg、ASR、VLM、云客户端和文档工具的具体实现；
- DOCX/PDF 的格式细节；
- 权限、预算和敏感信息管理。

### 4.3 保留并演化

- `ArtifactStore`：业务产物唯一存储和原子提交边界；
- `WorkspaceCache`：跨运行、跨 Checkpoint 的语义结果复用；
- `ProcessingContext/RunPolicy/RuntimeServices`：演化为 GraphRuntime 注入上下文，仍禁止秘密序列化；
- `StepSpec/StepOutcome`：演化为 `NodeSpec/NodeOutcome` 或兼容别名；它们是节点合同，不是第二个调度器；
- `EventSink/ProgressSink`：接收 Graph/Node/Task 的稳定事件；
- ports/adapters：继续隔离媒体、语音、视觉、云端、进程和文档中间件。

### 4.4 必须删除

等价切换验收后删除：

- `PipelineRunner` 的顺序调度循环；
- `StepRegistry` 的生产调度职责；
- Controller/Application 内绕过 Graph 的缓存短路和聚合编排；
- 仅服务旧 Runner、且没有 Artifact 迁移用途的兼容代码；
- 用户可见的双执行器开关。

冻结的对照 fixture 和 Artifact 读取适配器可以保留，但不得调用旧生产执行器。

## 5. Graph State 合同

### 5.1 Root JobState

仅保存小型、可 JSON 序列化的数据：

- `schema_version`、`graph_version`、`job_id`；
- 无秘密的请求快照和 `aggregate_mode`；
- Source 请求列表、当前队列位置；
- 每个 VideoGraph 的 thread/task 标识与结果 Artifact 引用；
- Aggregate 结果引用；
- 状态、问题摘要、能力/预算摘要；
- 最终输出引用。

### 5.2 VideoState

- `video_id`、Source 指纹与 Artifact 引用；
- 当前节点和已完成节点摘要；
- Artifact ID → path/digest/contract 的轻量引用；
- 待处理章节、视觉问题和疑难 ASR span 的稳定 ID；
- 节点能力、质量问题和降级摘要；
- 输出引用。

### 5.3 禁止进入 State/Checkpoint

- API Key、Authorization Header 或完整凭据对象；
- RuntimeServices、回调、锁、进程句柄、模型实例；
- 图片/音频/视频二进制；
- 完整 transcript、CourseIR、DocumentPlan、Document；
- 无上限的 Prompt、响应正文或 traceback；
- 无法稳定序列化的第三方对象。

大对象先写入 staging/ArtifactStore，State 只返回 `ArtifactRef` 的安全投影。凭据通过运行时 config 注入，永不持久化。

## 6. NodeExecutor 与事务合同

LangGraph 是唯一调度器；所有产生副作用的节点统一调用无调度职责的 `NodeExecutor`：

```text
cancel check
→ resolve and validate input ArtifactRefs
→ compute fingerprint
→ cache decide / cache-hit validate
→ acquire workspace and resource leases
→ create staging
→ execute node port/domain function
→ validate NodeOutcome and output contracts
→ atomically commit Artifacts
→ record WorkspaceCache
→ emit committed terminal event
→ return State delta
→ LangGraph writes next checkpoint
```

强制规则：

- 缓存判定完成前不得初始化 ASR/VLM/云客户端/Word 等昂贵端口；
- Node 只能写自己的 staging 和声明输出；不得直接改写其他节点 Artifact；
- 只有 `succeeded`/`degraded` 且通过校验的输出可以提交和缓存；
- Artifact 提交先于 CacheRecord，CacheRecord 先于 Node 返回；
- 节点完成事件只能在提交和缓存成功后发布；
- 动态任务也必须经过同一事务语义或等价的 TaskExecutor；
- 所有副作用必须幂等，重放不得重复产生云成本或覆盖有效产物。

崩溃恢复：

| 崩溃位置 | 恢复行为 |
|---|---|
| 提交前 | 正式产物不变；清理/忽略 staging 后重跑 |
| Artifact 提交后、缓存前 | 验证孤立 Artifact，满足合同则单向认领，否则重跑 |
| 缓存后、Checkpoint 前 | Graph 可能重放；缓存命中后返回相同引用，不重复模型调用 |
| Checkpoint 后 | 从下一待执行节点恢复 |

Checkpoint 提供同一次 Job 的执行恢复；WorkspaceCache 提供跨 Job 和跨 Graph Thread 的计算复用。二者不得互相替代。

## 7. Graph 与动态任务设计

### 7.1 Root JobGraph

- 接受一个或多个 `SourceRequest`；
- 首版按用户队列顺序进入 VideoGraph，避免多视频争抢 GPU/磁盘；
- 每个视频成功或 degraded 后记录 `VideoResultRef`；
- 必要视频失败时，Job 默认停止并保留之前结果；后续是否支持“跳过失败视频继续”另立版本，不在首版隐式加入；
- `aggregate_mode != none` 且至少两个有效结果时进入 AggregateGraph；
- JobFinalize 校验所有要求产物后写终态。

### 7.2 VideoGraph

等价迁移阶段按当前依赖和顺序包装现有步骤；质量阶段再演化目标节点。禁止在同一个检查点同时改变调度器与知识算法。

目标知识路径：

```text
transcript.normalize + frames.candidates
  → transcript.enrich / content.profile
  → visual.plan
  → visual.evidence
  → knowledge.course_ir
  → document.plan
  → chapter.compose[N]
  → chapter.validate[N]
  → chapter.repair[failed_only, max_once]
  → document.compile
  → document.validate
```

### 7.3 VisualGraph

- 修复现有 VisualEvidence 只拿到全局已选 8 帧、未消费约 600 候选帧的输入合同问题；
- 每个知识单元的视觉决策为 `none | supportive | required`，并记录视觉职责；
- `none` 不创建视觉任务；`required` 可围绕来源时间窗按需密集采样；
- 首版视觉任务串行循环，每次形成稳定 task ID 和独立结果；
- `RuntimeServices` 按视频惰性持有一个 VLM 实例；进程重启后允许重新加载，但同一活跃运行不得按问题重复加载；
- `no_match` 是正常证据结论，不是 provider 失败；不得用最近帧静默兜底；
- 云端不接收原始图片。

### 7.4 ChapterGraph

- 章节 ID 由 DocumentPlan 稳定生成；不得使用随机 ID；
- 每章独立指纹、缓存、生成、校验和落盘；
- 云端或本地生成失败只影响当前章；
- 先运行确定性校验，只对未达标章节调用 critic/repair；
- 首版每章最多一次修复，禁止无界循环；
- 全局归并只处理顺序、重复、风格和摘要，不得无来源重写事实。

### 7.5 AggregateGraph

- 本地聚合始终可用；云端聚合为增强；
- 聚合输入是各视频 Canonical Document/Document v3 Artifact 引用，不读取 UI DTO 中的正文副本；
- 聚合也使用独立 Job/Artifact/Checkpoint，不直接写入某个视频 Workspace；
- 云端批次必须逐批落盘和复用，后续失败不得丢弃成功批次；
- 输出继续包含 Markdown、Word、PDF 和来源回链。

## 8. 模型与决策政策

### 8.1 必须存在的本地基线

`LocalDecisionPolicy` 不依赖 LLM，负责：

- 权限、预算、可用性和路由；
- 课程基础画像与规则分块；
- 视觉需求初筛；
- 离线 DocumentPlan；
- 重试、降级、缓存和版本决策；
- 结构、来源和渲染能力校验。

即使所有模型初始化失败，只要存在最低可用转录，仍必须通过确定性路径生成完整文档并标记降级。

### 8.2 可选 ModelAdvisor

现有模型只有通过任务级门禁才能参与语义建议：

- Faster-Whisper：主/备转录；
- Qwen3-ASR：疑难音频 span 复核，不承担通用文本规划；
- Qwen3-VL-2B：视觉必要性建议、候选排序、OCR/板书/基础公式辅助和短上下文分类；不承担三小时全局规划或高质量全文写作。

准入门：环境健康、资源可承受、结构化输出稳定、黄金 fixture 优于确定性基线、失败可无损回退、无资源冲突。未通过则关闭该任务的 ModelAdvisor，不改变主图合同。

V6.0 不强制新增本地文本模型。未来可通过同一 Advisor 端口接入，模型选择/下载必须另获批准。

### 8.3 云端多阶段增强

允许在以下节点按价值和不确定度使用云端：

- 疑难 ASR/公式文本复核；
- 全局 DocumentPlan；
- 章节生成；
- 低分章节修复；
- 全局一致性检查；
- 云端聚合。

规则：

- 每次真实运行前展示数据类型、端点、角色模型链、调用上限和预算，并获得授权；
- 模型按角色配置，故障转移链不伪装为多模型审阅；
- 节点产出统一合同，本地和云端可替换；
- 成功批次立即落盘；失败后局部降级；
- 连续网络/限额/非法结构达到阈值后熔断，后续节点直接走本地；
- 云端调用指纹至少包含输入摘要、角色、模型、prompt/policy 版本和关键采样参数；
- 重放必须先命中结果缓存，禁止无理由再次付费。

### 8.4 图片云策略

- `cloud_text_authorized` 与 `cloud_image_authorized` 分离；
- 首版 `cloud_image_authorized` 默认且实际为 `false`；
- 当前云端模型不得收到图片字段、base64、文件上传或视频帧；
- 本地 VLM 的结构化视觉描述可以作为普通文本证据；
- 仅保留窄 `CloudVisionPort`，不得在首版实现隐式上传；
- 未来必须同时满足视觉模型配置和单独图片授权。

## 9. DocumentPlan 与 Document v3

### 9.1 设计原则

不得人工穷举所有课程模板，也不得让 LLM 直接生成任意 DOCX/XML。采用受约束文档编译链：

```text
User Editorial Brief + CourseIR + RendererCapabilityManifest
  → DocumentPlan（LLM 或本地策略生成）
  → Plan Validator/Compiler
  → Canonical Document v3
  → deterministic Markdown/Word/PDF renderers
```

### 9.2 DocumentPlan

表达编辑意图而非最终格式：

- 受众、用途、详略和语气；
- 章节结构和知识点聚合；
- 每章目标、重点和展开深度；
- 公式、例题、图片、表格、警告等表达选择；
- 图片职责与相邻内容；
- 布局提示和来源覆盖要求；
- 允许的降级方案。

用户只需提供大致偏好；LLM 在 Capability Manifest 内自主规划。未知组件或不支持布局必须有确定性 fallback。

### 9.3 RendererCapabilityManifest

首版保持小而通用：

- heading、paragraph、list、equation、table、image；
- container、callout、page_break；
- `full_width`、`image_text`、`two_column`、`compact_table` 等有限布局提示；
- source reference 与 `video-study://`；
- Markdown/Word/PDF 各能力和 fallback。

不得把课程语义模板全部写进 renderer。LLM 可以把通用原语组合成公式速查、定义—推导—例题、图文对照等结构。

### 9.4 Document v3

- 是渲染唯一正文事实源；
- 具备段落、列表、公式、表格、图片、容器、来源和布局提示；
- 公式保存规范表达、纯文本 fallback、置信度和精确来源；
- 图片保存 binding、职责、caption、解释和精确时间来源；
- 普通正文按知识点/证据组提供回链，避免每个短段重复链接；
- 公式和图片必须精确追溯；无法确认的公式标记不确定，不得补造；
- Word 优先生成原生数学对象；失败退化为高质量矢量/位图公式，不得静默丢失；
- 视觉方向参考 `高数_精炼版.docx` 的知识密度和层级，但补回来源、图片、语义样式与公式合同。

Document v2 只读；新实现只写 v3。聚合在迁移期允许读取 v2，经边界 Adapter 转成当前 Canonical View，不得在核心节点散布兼容判断。

## 10. 状态、降级与取消

统一终态：

- `succeeded`：必要产物完整并达到正常质量门；
- `degraded`：产物完整，但模型、视觉、云端或质量增强部分不可用；
- `failed`：必要节点全部实现失败，无法形成完整产物；
- `cancelled`：用户明确取消。

必要节点：Source 验证、最低可用音频/转录、Document 编译、要求的最终渲染。增强节点：第二 ASR、术语/公式修复、智能视觉、云端规划/写作/critic 等。

取消规则：

- 取消信号不进入 Checkpoint；节点和子进程使用 RuntimeServices 检查；
- 当前 staging 清理，已提交 Artifact 保留；
- Job 写 `cancelled` 后不恢复该 thread；用户再次启动创建新 Job 并复用 Artifact；
- 异常崩溃且 graph version 相同才恢复原 thread；
- “取消并清理”属于维护动作，只能在终止并释放租约后清理当前未提交状态，不得误删历史有效 Artifact。

## 11. 版本、缓存与持续 Bug 修复

采用四级版本：

| 版本 | 触发变化 | 失效/恢复行为 |
|---|---|---|
| `graph_version` | Graph 拓扑、State/Reducer、节点语义顺序 | 新建 thread；验证复用 Artifact；不恢复旧 Checkpoint |
| `implementation_version` | 节点代码 Bug 或算法变化 | 当前节点及必要下游重算 |
| `contract_version` | Artifact Schema/语义变化 | Adapter、迁移或相关节点重算 |
| `policy_version` | Prompt、模型角色、决策规则 | 仅失效相关模型/决策节点及必要下游 |

稳定要求：

- Node/Task ID 不得包含随机数；动态 ID 来自输入业务身份和版本；
- CacheRecord 包含 graph/node/contract/policy 版本、输入摘要和实际 capability；
- `offline/degraded` 缓存不能满足后续明确授权的高能力请求时，返回 `CAPABILITY_INSUFFICIENT`；
- 改 Prompt 不得导致 ASR/帧重新执行；改 renderer 不得导致知识链重跑；
- 改 Graph 只新建 thread，不得清空所有 Artifact；
- Bug 修复必须新增回归测试并提升最窄版本字段。

## 12. Workspace 与迁移

迁移原则：非破坏、惰性认领、底层优先复用、执行状态不转换。

可验证后优先复用：

- Source manifest/下载文件；
- 音频；
- 原始 ASR；
- 候选帧。

默认重算：

- 规范化/增强转录（规则和合同变化）；
- 全局选帧和视觉证据；
- CourseIR/KnowledgeUnits；
- DocumentPlan、Document v3 和渲染产物；
- 聚合产物。

路径和命名由执行阶段结合 WorkspaceLayout 最终确定，但必须满足：

- v2/v3 产物并存，不覆盖；
- legacy state 与 graph state 分开；
- Job/aggregate 有独立 workspace；
- 活动版本指针/manifest 原子写入；
- 失败迁移不修改旧产物；
- 旧产物不主动删除；
- 旧 Graph Checkpoint 不跨 graph version 转换。

具体矩阵见目标合同和执行计划；任何新增迁移规则必须先有 fixture 和回滚测试。

## 13. 错误、事件与诊断

稳定动态任务 ID 示例：

- `video:<video_id>`；
- `asr-span:<start_segment_id>-<end_segment_id>`；
- `visual:<question_id>`；
- `chapter:<chapter_id>`；
- `aggregate-batch:<batch_id>`。

事件至少包含：

- job/thread/checkpoint、graph/node/task/attempt ID；
- graph/node/contract/policy 版本；
- 状态、错误码、retryable、降级原因；
- 输入输出 Artifact ID；
- provider、模型角色、实际 capability；
- 缓存命中/失效原因；
- 耗时、token、调用次数和成本摘要；
- 推荐恢复节点。

事件不保存密钥、图片、完整 Prompt/响应或无限 traceback。原始技术异常写有界诊断 Artifact，可读日志使用稳定错误码和摘要。

`scripts/diagnostics/diagnose_workspace.py` 必须升级为 Graph-aware 只读诊断：识别 graph version、thread/checkpoint、最后失败 Node/Task、Artifact lineage、缓存原因、模型降级和安全恢复入口。`docs/diagnostics/problem-index.yaml` 登记 Node 错误族、owner、首个 Artifact、主测试和安全重跑点。

## 14. 测试与质量合同

### 14.1 永久工程门禁

- 云端 opt-in，未授权构造/请求为 0；
- 图片云端默认禁用；
- 密钥不进入 State/事件/缓存；
- Artifact 原子提交、缓存选择性失效；
- 取消、崩溃恢复、幂等重放；
- Application/Desktop/基础设施边界；
- JSON → Markdown → Word → PDF 与 `video-study://`；
- 历史 Workspace 不主动删除。

### 14.2 等价迁移门

- 当前 15 步的 Artifact、终态、缓存原因、取消和错误行为对照；
- URL、本地文件、单视频、多视频、本地聚合和云端聚合入口全部经过 Graph；
- 缓存命中前不初始化模型；
- GraphRuntime 切换前不删除旧 Runner；切换后生产调用归零再删除。

### 14.3 Graph 故障门

- 每个 Node 的 success/cache/degraded/fail/cancel；
- commit 前后、cache 前后、checkpoint 前后故障注入；
- 动态视觉/章节/聚合批次部分成功恢复；
- graph version 不兼容时新建 thread；
- 同版本异常中断恢复；
- GPU 互斥和 VLM 单视频单会话；
- 云端各节点失败、熔断和本地降级。

### 14.4 产物质量门

黄金样本至少三类：

1. 数学/公式：现有高数 Workspace；
2. 软件操作/强视觉：从现有资料筛选后由用户确认；
3. 纯讲授/弱视觉：从现有资料筛选后由用户确认。

指标至少包含：

- ASR 术语和疑难 span 修复；
- 章节结构、知识覆盖和重复率；
- 公式准确率、来源和 Word 呈现；
- 图片有效率、`none/supportive/required` 合理性和图文邻接；
- Source 回链覆盖；
- 页数、信息密度、孤立标题和分页；
- 云端调用、token、成本和缓存复用；
- 离线/降级完整性；
- GPU 峰值、模型加载次数、耗时和取消响应。

现有高数原版与精炼版用于视觉/编辑方向对照，不把精炼版缺少图片、来源和原生公式的实现细节当作目标合同。

### 14.5 完整离线验收

每个发布检查点按影响范围运行责任测试；正式切换和发布必须运行：

```text
conda activate ImageT10
python -m unittest discover -s tests
python -m compileall -q src tests
python -m pip check
git diff --check
```

真实云、真实模型、长视频和便携构建是独立授权门，不得为了“全绿”擅自执行。

## 15. 发布与完成定义

V6.0/1.0.0 完成必须同时满足：

1. LangGraph 接管 Source、Video、Aggregate、Publish 全链路；
2. 生产入口只调用 GraphRuntime，旧 Runner/Registry 调度和 UI 缓存绕行已删除；
3. NodeExecutor 事务、Graph Checkpoint、ArtifactCache 分工有故障注入证据；
4. 纯离线、模型增强、云端增强和各级降级路径通过；
5. DocumentPlan、Document v3 和三个 renderer 合同通过；
6. 历史 Workspace 迁移 fixture 通过，旧产物未被覆盖；
7. Graph-aware 诊断和错误索引可定位动态任务；
8. 三类黄金样本达到批准的质量门；
9. 完整离线验收全绿；授权的真实烟测有独立事实记录；
10. `项目索引.md`、`AI执行入口.md`、当前状态、architecture YAML、问题索引、执行事实和版本号一致；
11. 临时双路、迁移脚手架和僵尸代码按删除清单清理；
12. 用户确认正式发布，产品版本由 alpha/beta 升为 `1.0.0`。

## 16. 已知实施风险与固定退路

| 风险 | 固定退路 |
|---|---|
| Windows 下 SQLite Checkpointer 不稳定 | 更换 Checkpointer adapter；Graph/Artifact 合同不变 |
| Qwen3-VL 局部决策无增益 | 关闭对应 ModelAdvisor，使用确定性策略 |
| Word 原生公式不可靠 | 使用规范矢量/位图公式并保留语义源 |
| 黄金样本质量提升不足 | 调整 Evidence/DocumentPlan/章节节点，不重做执行框架 |
| 新 Graph 版本无法恢复旧 thread | 新建 thread，验证复用 Artifact；不转换旧 Checkpoint |
| 云端预算、网络或输出失败 | 节点级熔断和本地降级；保留成功批次 |

这些风险是检查点内必须验证的实施风险，不构成重新讨论架构方向的理由。若固定退路也失败，立即停止当前检查点并向用户报告，不得扩大修改范围掩盖失败。
