# V6.0 LangGraph 全链路升级执行计划

> 状态：`CP0 validated`（2026-08-20 15:21 Asia/Shanghai）；生产仍为 0.5.1/V4，未安装 LangGraph。  
> 架构权威：[V6.0 LangGraph 全链路架构升级方案](V6.0%20LangGraph全链路架构升级方案.md)。  
> 机器合同：[V6.0 LangGraph 全链路目标合同](V6.0%20LangGraph全链路目标合同.yaml)。  
> 当前基线：产品 `0.5.1`；目标：架构 V6.0、产品 `1.0.0-alpha → 1.0.0`。

## 0. 执行总则

本文件是 V6.0 唯一实施顺序和恢复点来源。主方案负责“做成什么”，目标合同负责“机器应检查什么”，本文件只负责“按什么顺序做、如何验收、失败后退到哪里”。

强制规则：

1. 严格按 P0→P8 推进；每个 CP 必须记录机器证据后才能进入下一阶段。
2. P1–P4 只迁移编排，不改变知识、视觉、Prompt、Document v2 内容或样式。
3. P5–P6 才升级质量；一次只替换责任明确的节点组。
4. 修改前先增加失败回归测试；任务在同一目录内串行执行，避免写竞争。
5. 不删除、覆盖或批量迁移历史 Workspace；不清理用户 dirty worktree。
6. 未获单独授权不得执行云请求、模型下载/重装、长视频重跑、在线烟测、便携包构建。
7. 每个阶段结束更新本计划状态、`当前架构升级状态.yaml` 和必要执行事实；未实现内容不得写入当前运行合同。
8. 发生非当前阶段问题时先记录，不顺手扩展；阻塞当前门禁才允许最小修复。

## 2. P0：基线与合同冻结 → CP0

### 任务

1. 只读诊断代表 Workspace：至少高数和一个短视频；保存运行状态、Artifact、缓存和错误摘要，不重跑长视频。
2. 运行当前完整离线基线：
   - `python -m unittest discover -s tests`
   - `python -m compileall -q src tests`
   - `python -m pip check`
   - `git diff --check`
3. 记录当前测试数、失败、环境和 dirty worktree；失败必须先判断是否为基线既有问题。
4. 建立只读对照 fixture：
   - 单视频成功；
   - 缓存命中；
   - 取消；
   - 节点失败；
   - 本地/URL Source；
   - 本地聚合；
   - 云端聚合使用 fake/recording，不发真实请求。
5. 固化当前 15 步的 Node/Artifact/事件/缓存原因快照，只比较稳定语义，不冻结随机 run ID、绝对时间和非合同日志文本。
6. 评估并选择本地持久化 Checkpointer adapter；优先 SQLite。依赖新增/安装前取得单独授权并固定兼容版本范围。
7. 将主方案和目标合同转成架构守卫测试骨架，但不修改当前 `docs/architecture/*.yaml` 的 active 事实。

### CP0 完成门

- 当前离线基线结果已记录；

## 3. P1：NodeExecutor 等价提取 → CP1

### 目标

把 `PipelineRunner._run_step` 中已验证的单节点事务提取为无调度职责的 `NodeExecutor`，旧 Runner 暂时调用它。此阶段不引入 LangGraph执行路径。

### 任务顺序

1. 为以下事务窗口增加失败测试：缓存检查、staging、validate、commit、cache record、事件、取消和 finally 清理。
2. 新增 `execution/node_executor.py`（建议路径），只负责一个 Node：
   - 输入解析与验证；
   - fingerprint/cache；
   - staging/execute/validate；
   - atomic commit/cache record；
   - terminal event/state-neutral result；
   - cancellation 和异常分类。
3. `PipelineRunner` 改为调用 NodeExecutor，保留现有顺序调度和状态机。
4. 统一 cache-hit 和 execute-hit 的 NodeOutcome 校验，确保昂贵端口仍惰性加载。
5. 为 commit 后/cache 前等崩溃增加 Artifact 单向认领策略和测试；不得把不完整 Artifact 当命中。
6. 保持当前公开结果、事件终态、错误码、缓存原因和 Artifact 路径不变。

### 主要文件

- `src/video_study/execution/node_executor.py`（新增）
- `src/video_study/execution/runner.py`
- `src/video_study/execution/contracts.py`
- `src/video_study/execution/artifacts.py`
- `src/video_study/execution/cache.py`
- `tests/test_pipeline_runner.py`
- `tests/test_workspace_artifacts.py`
- `tests/test_workspace_cache.py`

### CP1 完成门

- 旧 Runner所有现有测试通过；
- 新 NodeExecutor合同测试覆盖主方案 §6 的四类崩溃窗口；
- 15 步对照 Artifact/缓存/事件无语义变化；
- 生产仍由旧 Runner调度；无 LangGraph依赖泄漏到领域模块。

### 回滚/续跑

- 回滚：Runner恢复内联执行逻辑；NodeExecutor新增文件可删除。
- 续跑：从 P2 Graph State/GraphRuntime失败测试开始。

## 4. P2：单视频 LangGraph 等价接管 → CP2

### 目标

用 LangGraph完整表达当前单视频 15 步，Graph Node统一调用 NodeExecutor；知识和文档产物保持 v2 等价。

### 任务顺序

1. 在批准依赖变更后加入并固定 LangGraph/Checkpointer依赖；运行 `pip check`。
2. 新增最小 GraphRuntime模块：
   - `graph_state.py`：安全、轻量、可序列化 State；
   - `graph_runtime.py`：compile/invoke/resume/stream；
   - `graphs/video_graph.py`：当前 15 步等价图；
   - `graph_events.py`：Graph事件映射现有 EventSink/ProgressSink。
3. Graph State只存 ArtifactRef安全投影；秘密和 RuntimeServices只通过运行时注入。
4. 使用版本化 thread/checkpoint；同版本异常中断可恢复，版本不符拒绝恢复。
5. 给 NodeExecutor增加 Graph Node adapter；不得在每个节点复制缓存/提交逻辑。
6. 建立旧 Runner vs VideoGraph差分测试：
   - 成功、缓存、degraded、失败、取消；
   - force/force_asr/force_summary；
   - 未授权云请求为零；
   - 输出与事件稳定字段等价。
7. 此阶段 Graph仅作为对照入口，不切生产，不更改 Document v2。

### 主要文件

- `pyproject.toml` / lock 或依赖清单
- `src/video_study/execution/graph_state.py`
- `src/video_study/execution/graph_runtime.py`
- `src/video_study/execution/graph_events.py`
- `src/video_study/execution/graphs/video_graph.py`
- `src/video_study/execution/bootstrap.py`
- 新增 Graph State/Runtime/差分测试

### CP2 完成门

- 单视频全部15步经 LangGraph运行；
- 旧 Runner和 Graph差分测试全绿；
- Checkpoint不含秘密和大对象；
- crash/replay不会重复模型或云调用；
- 当前生产入口仍未切换，便于回滚。

### 回滚/续跑

- 回滚：移除 Graph对照入口和新增依赖，旧 Runner仍可运行。
- 续跑：从 P3 SourceGraph/JobGraph/AggregateGraph开始。

## 5. P3：全链路入图与生产切换 → CP3

### 目标

Source、本地/URL、单/多视频、聚合和发布全部使用 LangGraph；Application生产入口切换 GraphRuntime，旧 Runner仅保留对照测试，不再接收生产调用。

### 任务顺序

1. 新增 `JobRequest/JobResult/JobHandle` 或等价 DTO：支持多个 Source 和 `aggregate_mode`；凭据保持运行时字段。
2. 建立 SourceGraph：
   - local.resolve；
   - url.preflight/url.acquire/source.verify；
   - URL缓存也由 Graph/Artifact缓存决定。
3. 建立 JobGraph：首版按队列顺序调用 VideoGraph；发出带 video_id 的进度事件。
4. 建立 AggregateGraph：先包装当前本地/云端聚合，保持输出等价；聚合作为独立 Job/Workspace。
5. Application Service改为提交 Graph Job；Desktop Controller取消自行 `cached_result` 跳过和自行队列业务编排，只投影 Graph事件。
6. `pipeline.process_video/run_all`、URL兼容入口和聚合公开函数只调用 GraphRuntime。
7. 增加 UI逻辑等价测试：本地、URL、多视频、取消、本地聚合、fake云端聚合和缓存恢复。
8. 统计旧 Runner/Registry生产调用必须为零；保留冻结差分测试直至 CP4。

### 主要文件

- `src/video_study/application/requests.py`
- `src/video_study/application/processing.py`
- `src/video_study/desktop/controller.py`
- `src/video_study/execution/graphs/job_graph.py`
- `src/video_study/execution/graphs/source_graph.py`
- `src/video_study/execution/graphs/aggregate_graph.py`
- `src/video_study/execution/bootstrap.py`
- `src/video_study/pipeline.py`
- `src/video_study/aggregate.py`
- 对应 Application/Desktop/Source/Aggregate/Graph测试

### CP3 完成门

- 所有业务数据处理入口都到达 GraphRuntime；
- Controller/Application不存在生产编排和缓存绕行；
- 单视频、多视频和聚合UI等价链路通过；
- 旧 Runner没有生产调用，但代码尚未删除；
- 当前 v2产物和质量行为不变。

### 回滚/续跑

- 回滚：Application composition root切回旧 Runner；Graph产物使用独立 state，不覆盖旧产物。
- 续跑：从 P4 删除测试与生产旧路径开始。

## 6. P4：删除旧调度器与清理边界 → CP4

### 目标

消除双执行器，完成“LangGraph唯一编排器”的不可逆架构切换。

### 任务顺序

1. 删除 PipelineRunner顺序调度和 StepRegistry生产调度职责；保留/重命名必要 NodeSpec合同。
2. 删除旧 composition root、旧聚合编排、Controller缓存短路和生产双路开关。
3. 将仍有价值的 Runner测试迁成 NodeExecutor/GraphRuntime合同测试；删除只验证已移除实现形态的测试。
4. 更新当前 `docs/architecture/pipeline-steps.yaml`、`module-boundaries.yaml` 和问题索引，使其反映已切换 Graph事实。
5. 运行引用扫描，确认生产代码没有旧 Runner/Registry调度调用和无效兼容桥。
6. 更新当前状态为 `graph_cutover_validated`，但产品仍处于 alpha，知识/文档质量升级尚未开始。

### CP4 完成门

- GraphRuntime是唯一生产编排器；
- 没有用户可见或隐藏生产双路；
- 当前功能回归全绿；
- active architecture YAML与代码一致；
- 完整离线验收通过。

### 回滚/续跑

- CP4提交前的 CP3是最后代码级回滚点；CP4后不恢复旧 Runner，问题通过修复 Graph/NodeExecutor解决。
- 续跑：从 P5视觉候选回归测试开始。

## 7. P5：本地决策、模型路由与证据质量 → CP5

### 目标

保持离线确定性链完整，修复 ASR/视觉真实瓶颈，并让现有本地模型和云端按节点有限增强。

### 任务顺序

1. 修复 VisualEvidence候选输入合同：生产必须消费 `frames.candidates` 或目标时间窗密集采样，不再只比较全局 selected帧。
2. 新增 `LocalDecisionPolicy`：内容画像、规则分块、视觉初筛、离线计划、能力路由和降级。
3. 新增可选 `ModelAdvisor`任务白名单和准入评测；不得引入必需本地文本模型。
4. ASR增强：主ASR完成全量；第二ASR只处理低置信度/术语/公式疑难 span；词典采用基础/项目/候选账本，禁止无证据污染。
5. VisualGraph：`none/supportive/required`、视觉职责、目标时间窗、候选/密集采样、VLM逐任务循环、独立缓存和 expected no_match。
6. 云端角色化：疑难文本、计划、章节、repair、一致性、聚合；实现节点级预算、结果落盘和熔断。
7. 强制文本/图片权限分离；首版图片云调用路径保持不可达并有守卫测试。
8. 增加每个模型节点的 local/cloud/failure/degraded矩阵；实测模型和云端仍需单独授权。

### 主要责任区

- `knowledge/*` 中内容画像、规划、视觉检索、CourseIR、organizer和cloud payload模块
- `asr.py`、`execution/adapters/vision.py`、providers/ports
- Graph条件路由、动态task cache、资源租约
- 对应ASR/VLM/visual/cloud/Graph测试

### CP5 完成门

- 所有模型不可用时仍生成完整 degraded文档；
- 现有模型只在准入任务中参与；
- 高数候选检索实际覆盖候选池/目标时间窗；
- 云端任一阶段失败不丢成功批次、不整体回退；
- 图片云端请求为零；
- VLM单视频单会话和GPU串行有测试/事件证据。

### 回滚/续跑

- 回滚：关闭 Advisor和云端增强路由，保留 LocalDecisionPolicy和修复后的确定性证据链。
- 续跑：从 P6 DocumentPlan Schema失败测试开始。

## 8. P6：DocumentPlan、Document v3 与渲染 → CP6

### 目标

建立“用户意图/LLM规划 → 受约束DocumentPlan → Canonical Document v3 → 确定性渲染”，改善知识结构、公式、图文布局和来源呈现。

### 任务顺序

1. 定义最小 RendererCapabilityManifest和DocumentPlan Schema；未知组件/布局有fallback。
2. 实现离线 DocumentPlan；云端计划作为同合同增强，失败退回离线。
3. 章节级 compose/validate/repair：独立Artifact/缓存，确定性校验优先，每章最多一次修复。
4. 定义 Document v3：通用内容原语、公式、表格、图片binding、container、layout hint和source refs。
5. 实现 v2只读边界Adapter；核心Graph只消费当前Canonical View，新产物只写v3。
6. Markdown renderer支持v3语义与公式；Word优先原生公式，失败退化为高质量公式图；PDF保持Word优先和内置fallback。
7. 增加页面QA：公式缺失、图片/解释分离、孤立标题、分页、重复来源、链接和空白页。
8. 使用高数缓存从知识阶段新旧对照，不重跑长视频；人工和机器检查前两页及全篇结构。

### CP6 完成门

- DocumentPlan本地/云端路径同Schema；
- Document v3是新渲染唯一正文事实源；
- v2未覆盖，v3与新输出并存；
- 公式、图片和来源从JSON贯通Markdown/Word/PDF；
- 高数产物在结构、公式、密度上达到目标方向；
- 云端不可用时仍输出完整degraded v3。

### 回滚/续跑

- 回滚：活动版本指针仍指向v2产物；保留v3试验Artifact，不覆盖旧文件。
- 续跑：从 P7迁移fixture和Graph诊断开始。

## 9. P7：迁移、诊断与质量发布候选 → CP7

### 任务顺序

1. 实现并测试目标合同中的Artifact迁移矩阵；每种历史版本至少一个只读fixture。
2. 旧Graph/checkpoint不转换；graph version不符时新thread并认领合法Artifact。
3. 升级 `diagnose_workspace.py`：Graph/Thread/Checkpoint/Node/Task/Artifact lineage/能力/成本/恢复入口。
4. 扩展 `problem-index.yaml`：Node错误族、owner、主测试、首个Artifact和安全重跑点。
5. 为每个Node加入故障注入；覆盖commit/cache/checkpoint窗口、动态任务部分成功和GPU互斥。
6. 从现有数据筛选强视觉、弱视觉样本并请用户确认；与高数组成黄金集。
7. 建立质量报告：结构、重复、公式、图片、来源、页数、成本、耗时和显存。
8. 只用缓存完成高数质量候选；真实长视频/VLM/云端测试分别请求授权。
9. 完成alpha→beta候选评审；任何关键质量门失败则留在P7修复责任节点。

### CP7 完成门

- 历史Workspace迁移矩阵全绿且旧文件摘要不变；
- Graph-aware诊断能给出动态任务责任和恢复点；
- 三类黄金样本有可比报告；
- 故障/降级/资源/成本测试通过；
- 没有关键P0/P1缺陷；满足发布候选条件。

### 回滚/续跑

- 回滚：活动版本继续指向上个稳定产物；不删除v3和诊断证据。
- 续跑：P8完整收尾。

## 10. P8：发布与删除门 → CP8

## 12. Agent 每个检查点的交接格式
