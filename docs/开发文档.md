# 知影开发文档

> V4.0 架构；产品版本 0.4.0。机器可校验合同优先于本页叙述。

## 快速定位

1. 读 [`MEMORY.md`](../MEMORY.md) 与 [`AI执行入口.md`](../迭代升级/AI执行入口.md)。
2. 对具体视频工作区运行：`.venv\Scripts\python.exe scripts\diagnose_workspace.py workspace\<video_id>`。
3. 用输出的 `step_id/error_code` 查 [`problem-index.yaml`](diagnostics/problem-index.yaml)。
4. 只读对应 owner、Artifact 与测试；先添加失败回归测试，再修改最小责任模块。

## 稳定架构

- `application/`：处理用例、DTO、后台 Handle；不依赖 Tk。
- `desktop/`：Controller 状态机、Tk View、设置边界；只调用 Application Service。
- `execution/`：ProcessingContext、StepRegistry、PipelineRunner、ArtifactStore、WorkspaceCache、ports 与具体 adapters。
- `execution/steps/`：15 个生产 Step；注册表是步骤拓扑唯一真相。
- `knowledge/`：LessonPlan、CourseIR、视觉问题/证据、KnowledgeUnit、自检与 Document v2 适配。
- `pipeline.py`：旧公开函数的薄兼容门面，不承载编排。
- `render.py`：Canonical Document v2 到 Markdown、Word、PDF 的三端渲染。

机器可查询合同：

- [`module-boundaries.yaml`](architecture/module-boundaries.yaml)：owner、公开接口、依赖边界、Artifact、Step、测试。
- [`pipeline-steps.yaml`](architecture/pipeline-steps.yaml)：Step 目录；由合同测试逐字段对照注册表。
- [`problem-index.yaml`](diagnostics/problem-index.yaml)：错误前缀、首查 Artifact、owner、测试和安全重跑起点。

## 默认数据流

```text
source.probe
├─ audio.extract → transcript.decode → transcript.normalize
└─ frames.candidates → frames.select
   transcript.normalize → knowledge.plan
   knowledge.plan + frames.select → visual.jobs → visual.evidence
   transcript.normalize + frames.select → frames.semantics
   knowledge.plan + visual.evidence → knowledge.course_ir
   CourseIR + plan + evidence + semantics → knowledge.units → knowledge.selfcheck
   全部知识 Artifact → document.assemble → Canonical Document v2
   Document v2 → render.bundle → Markdown → Word → PDF
```

每个 Step 声明 dependencies、inputs、outputs、config_keys、capability、degradation、owner、tests、error prefix 和 contract version。缓存只比较声明过的指纹材料；输出缺失或损坏时从最小责任 Step 重跑。

## Artifact 与工作区

每个视频的 Canonical Workspace 位于 `workspace/<video_id>/`：

- `manifest.json`
- `audio/audio.flac`
- `transcript/raw.json`、`transcript/transcript.json`、SRT
- `images/candidates.json`、`images/keyframes.json` 及图片目录
- `knowledge/lesson-plan.json`、`visual-jobs/`、`visual-evidence.json`、`course-ir.json`、`knowledge-units.json`、`selfcheck.json`
- `knowledge/document.json`（只写 Schema v2）
- `state/cache/<step>.json`、`state/pipeline-state.json`、`state/runs/<run_id>.jsonl`

旧 Workspace 通过 `LegacyArtifactAdapter` 单向只读认领；Document v1 只允许 `v1_to_v2` 读取迁移。生产代码不写 v1、不写 `runtime-events.json`，也不生成 v2→v1 视图。历史文件不主动删除。

## 中间件与授权

Step 依赖 `MediaPort`、`SpeechPort`、`VisionPort`、`CloudJsonPort`、`DocumentPort`，具体实现只在 composition root 惰性构造。完全缓存、离线或未授权路径不会初始化无关模型/客户端。

云推理默认关闭。只有 `RunPolicy.cloud_authorized=true` 且 Application 提供显式凭据时才允许构造 CloudPort；请求共享同一个预算账本。测试和诊断不得发真实请求。

本地 VLM 是单视频会话：逐任务缓存先于 preflight/cold load；首个真实未命中任务才加载模型；OOM/会话失败触发批次熔断；批次结束关闭会话。

## Document 与播放

Canonical Document v2 的 `content_blocks` 是正文唯一事实源，`source_refs` 保存 segment、时间与 `video-study://play/<video_id>?t=<seconds>`。Markdown、Word、PDF 和聚合直接消费 v2。协议由本地桌面处理器解析到真实视频和时间戳，不打开网页。

## 测试与验收

```powershell
$env:PYTHONPATH='src;.'
.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
.venv\Scripts\python.exe -m compileall -q src tests
node --check scripts/render_docx.mjs

```

关键守卫位于 `tests/test_architecture_boundaries.py` 与 `tests/test_documentation_contracts.py`：阻止 Web 服务、跨层导入、秘密进入 ProcessingOptions、文档目录漂移、Step/owner/error/test 路径失真。

## 产品边界

- 仅原生 Windows 桌面与 CLI；不得增加 Web UI、HTTP 服务、端口或 `serve`。
- `.env` 只由授权设置边界处理；不打印、复制、提交秘密。
- `Resource/`、`workspace/`、`output/`、`models/` 是本地数据/产物，不是源码。
- 保持 JSON → Markdown → Word → PDF 和时间戳可追溯。
